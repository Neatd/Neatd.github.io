## 1. 그리디 알고리즘(Greedy Algorithm)

### 그리디란?

그리디는 **매 단계에서 가장 유리해 보이는 선택을 반복하는 알고리즘**이다.

예를 들어 여러 선택지 중에서 매번 가장 큰 숫자를 고르거나, 가장 적은 비용이 드는 선택지를 먼저 고르는 방식이다.

복잡한 미래 상황을 모두 계산하지 않고 지금 선택할 수 있는 최선의 행동을 결정한다는 점이 특징이다.

하지만 여기서 주의해야 한다.

**지금 가장 좋은 선택이 항상 최종적으로 가장 좋은 결과를 만드는 것은 아니다.**

그리디를 사용하기 전에 현재의 선택을 반복해도 최적의 결과가 만들어지는지 확인해야 한다.

### 언제 그리디를 떠올릴까?

문제를 읽었을 때 다음과 같은 특징이 보이면 그리디를 고려할 수 있다.

- 가장 큰 값이나 가장 작은 값부터 선택할 수 있다.
- 특정한 우선순위에 따라 선택을 반복할 수 있다.
- 매번 선택한 결과를 되돌릴 필요가 없을 것 같다.
- 정렬한 뒤 앞에서부터 처리하는 방식이 자연스럽다.

다만 이런 특징만으로 그리디가 정답이라고 확신해서는 안 된다.

핵심은 선택 기준을 만드는 것보다 **그 선택이 왜 항상 유효한지 설명할 수 있는가**에 있다.

### 1.1 그리디 예제 ① 동전 개수 최소화

#### 문제를 이해해 보자

사용할 수 있는 동전이 다음과 같다고 가정하자.

```python
coins = [1000, 500, 100, 50, 10]
```

거슬러 주어야 할 금액이 2,760원이라면 가능한 한 적은 수의 동전을 사용하고 싶다.

동전을 많이 사용하는 것보다 큰 금액의 동전부터 사용하는 것이 유리해 보인다.

#### 풀이 아이디어

큰 동전부터 가능한 만큼 사용한다.

2,760원을 예로 들면 다음과 같다.

| 동전 | 사용 개수 | 남은 금액 |
|---|---:|---:|
| 1,000원 | 2 | 760원 |
| 500원 | 1 | 260원 |
| 100원 | 2 | 60원 |
| 50원 | 1 | 10원 |
| 10원 | 1 | 0원 |

총 7개의 동전을 사용한다.

여기서 중요한 연산은 두 가지다.

- `//`: 현재 동전을 몇 개 사용할 수 있는지 계산
- `%`: 해당 동전을 사용한 후 남은 금액 계산

#### Python 구현

```python
def min_coins(amount):
    coins = [1000, 500, 100, 50, 10]
    count = 0

    for coin in coins:
        count += amount // coin
        amount %= coin

    return count


print(min_coins(2760))  # 7
```

#### 왜 정답일까?

이 예제의 동전 체계에서는 큰 단위가 바로 아래 작은 단위의 배수다.

따라서 작은 동전 여러 개를 사용해야 하는 상황을 큰 동전 하나로 대체할 수 있다.

하지만 모든 동전 체계에서 이 방법이 통하는 것은 아니다.

예를 들어 동전이 다음과 같다고 가정하자.

```python
coins = [1, 4, 6]
amount = 8
```

큰 동전부터 사용한다면 `6 + 1 + 1`로 3개가 필요하다.

하지만 실제 최적의 선택은 `4 + 4`로 2개다.

즉, **동전의 종류가 임의로 주어지는 경우 큰 동전부터 선택하는 방법은 실패할 수 있다.**

이런 경우에는 다이나믹 프로그래밍(DP)을 고려해야 한다.

#### 시간 복잡도

동전 종류가 K개라면 시간 복잡도는 `O(K)`다.

금액의 크기만큼 반복하는 것이 아니라 각 동전 종류를 한 번씩 확인하기 때문이다.

**복습 포인트:** 그리디 문제에서는 구현보다 선택의 정당성을 확인하는 과정이 중요하다.

#### 1.2 그리디 예제 ② 제한된 연속 선택에서 최댓값 만들기

#### 핵심 상황

여러 숫자 중 하나를 선택하여 총 M번 더할 수 있다고 가정하자.

단, 같은 위치의 숫자는 연속해서 K번까지만 선택할 수 있다.

이때 합계를 최대한 크게 만들고 싶다.

핵심은 당연히 가장 큰 숫자를 많이 사용하는 것이다.

그러나 연속 선택 횟수에 제한이 있기 때문에 가장 큰 숫자만 계속 선택할 수는 없다.

#### 어떻게 선택해야 할까?

예를 들어 숫자가 다음과 같다고 하자.

```python
numbers = [3, 8, 5, 2]
M = 9
K = 2
```

가장 큰 숫자는 8이고, 두 번째로 큰 숫자는 5다.

8을 연속 두 번 선택한 다음 5를 한 번 선택하면 다시 8을 사용할 수 있다.

선택 순서는 다음과 같다.

```text
8 → 8 → 5 → 8 → 8 → 5 → 8 → 8 → 5
```

결과는 63이다.

여기서 중요한 규칙은 `8, 8, 5`라는 패턴이 반복된다는 것이다.

#### 반복문을 이용한 구현

```python
def max_sum(numbers, m, k):
    numbers.sort(reverse=True)

    first = numbers[0]
    second = numbers[1]

    total = 0
    consecutive = 0

    for _ in range(m):
        if consecutive == k:
            total += second
            consecutive = 0
        else:
            total += first
            consecutive += 1

    return total
```

이 방법은 이해하기 쉽지만 M이 커질수록 반복 횟수가 늘어난다.

#### 수학적으로 최적화하기

가장 큰 수를 K번 선택하고 두 번째로 큰 수를 한 번 선택하므로 반복 패턴의 길이는 `K + 1`이다.

따라서 가장 큰 수가 등장하는 횟수는 다음과 같다.

$$
\text{firstCount}
=
\left\lfloor\frac{M}{K+1}\right\rfloor K
+
M \bmod (K+1)
$$

나머지 횟수에는 두 번째로 큰 수가 등장한다.

$$
\text{secondCount} = M-\text{firstCount}
$$

이렇게 계산하면 실제로 M번 반복하지 않아도 된다.

```python
def max_sum(numbers, m, k):
    first, second = sorted(numbers, reverse=True)[:2]

    first_count = (m // (k + 1)) * k
    first_count += m % (k + 1)

    second_count = m - first_count

    return first * first_count + second * second_count
```

정렬에 `O(N log N)`이 걸리며, 이후 합계를 계산하는 데에는 상수 시간이 필요하다.

#### 자주 놓치는 부분

연속 선택 제한이 **숫자 값이 아니라 배열의 인덱스**에 적용되는 경우, 동일한 최댓값이 두 위치에 존재한다면 번갈아 선택할 수 있다.

예를 들어 `[8, 8, 3]`이라면 서로 다른 두 위치의 8을 번갈아 선택해 모든 횟수에서 8을 사용할 수 있다.

위 코드도 두 번째로 큰 값이 8이 되므로 이 경우를 처리할 수 있다.

**복습 포인트:** 반복되는 선택 규칙이 보이면 직접 시뮬레이션하기 전에 패턴의 길이와 반복 횟수를 계산할 수 있는지 확인하자.

#### 1.3 그리디 예제 ③ 최솟값 중 최댓값 찾기

#### 핵심 상황

여러 행으로 구성된 숫자 배열이 있다고 가정하자.

한 행을 선택하면 반드시 해당 행의 가장 작은 숫자를 가져가야 한다.

그렇다면 어떤 행을 선택하는 것이 가장 유리할까?

```text
7  2  9
4  6  8
5  3  7
```

첫 번째 행의 최솟값은 2다.

두 번째 행의 최솟값은 4다.

세 번째 행의 최솟값은 3이다.

따라서 두 번째 행을 선택해야 4라는 가장 큰 결과를 얻을 수 있다.

#### 풀이 아이디어

문제를 두 단계로 나누면 된다.

먼저 각 행에서 가장 작은 값을 구한다.

그다음 그 값들 중 가장 큰 값을 선택한다.

즉, `max(min(row))` 구조다.

#### Python 구현

```python
def choose_card(board):
    return max(min(row) for row in board)


board = [
    [7, 2, 9],
    [4, 6, 8],
    [5, 3, 7],
]

print(choose_card(board))  # 4
```

행이 N개이고 각 행의 열이 M개라면 전체 시간 복잡도는 `O(N × M)`이다.

#### 이 문제에서 기억할 것

이 문제의 핵심은 복잡한 알고리즘이 아니라 조건을 정확하게 해석하는 것이다.

행을 선택하는 것은 자유지만, 행 안에서는 가장 작은 숫자를 선택해야 한다.

따라서 전체 배열에서 가장 큰 숫자를 찾는 것과는 완전히 다른 문제가 된다.

**복습 포인트:** 최솟값과 최댓값이 함께 등장하는 문제는 어떤 단위에서 `min`을 계산하고 어떤 단위에서 `max`를 계산하는지부터 구분하자.

#### 1.4 그리디 예제 ④ 1까지 빠르게 줄이기

#### 핵심 상황

양의 정수 N을 1로 만들어야 한다.

가능한 연산은 다음 두 가지다.

1. N에서 1을 뺀다.
2. N이 K로 나누어떨어질 때 N을 K로 나눈다.

목표는 연산 횟수를 최소화하는 것이다.

#### 왜 나누기를 우선할까?

1을 빼는 연산은 숫자를 조금씩 줄인다.

반면 나누기는 한 번에 숫자를 크게 줄일 수 있다.

예를 들어 N=28, K=3이라고 해보자.

```text
28 → 27 → 9 → 3 → 1
```

총 네 번의 연산으로 1을 만들 수 있다.

먼저 28에서 1을 빼서 3의 배수로 만든 뒤, 나누기를 반복한 것이다.

#### 기본 구현

```python
def reduce_to_one(n, k):
    count = 0

    while n > 1:
        if n % k == 0:
            n //= k
        else:
            n -= 1

        count += 1

    return count


print(reduce_to_one(28, 3))  # 4
```

이 코드는 직관적이지만 나누어떨어질 때까지 1을 여러 번 빼야 할 수 있다.

#### 더 효율적인 구현

1을 한 번씩 빼는 대신 다음 K의 배수까지 몇 번 빼야 하는지 한꺼번에 계산할 수 있다.

```python
def reduce_to_one(n, k):
    count = 0

    while n >= k:
        remainder = n % k

        count += remainder
        n -= remainder

        n //= k
        count += 1

    count += n - 1

    return count
```

이 방식에서는 반복마다 나누기를 수행하므로 나누기가 가능한 구간에서 반복 횟수가 크게 줄어든다.

#### 주의할 점

이 문제에서는 N과 K가 2 이상의 정수이며, 나누어떨어질 때 나누기를 선택하는 것이 유리하다는 조건을 활용한다.

다른 문제에서 연산 비용이 서로 다르거나 추가적인 제약이 있으면 같은 전략을 그대로 적용할 수 없다.

**복습 포인트:** 반복해서 1씩 줄이는 상황이 보이면, 나머지 연산으로 여러 번의 감소를 한 번에 계산할 수 있는지 생각해 보자.

## 2. 구현(Implementation)

### 1.1 구현 문제란?

구현은 생각한 풀이를 실제 코드로 정확하게 옮기는 과정이다.

코딩테스트에서는 특히 **문제의 규칙은 이해했지만, 조건을 코드로 옮기다가 실수하기 쉬운 문제**를 구현 유형으로 다루는 경우가 많다.

대표적으로 다음 두 유형이 있다.

- **시뮬레이션:** 문제에 주어진 규칙을 순서대로 실행한다.
- **완전 탐색(Brute Force):** 가능한 경우를 모두 확인한다.

예를 들어 캐릭터를 방향에 따라 이동시키거나, 특정 조건을 만족하는 시각의 개수를 세는 문제가 여기에 해당한다.

구현 문제에서 가장 중요한 것은 어려운 알고리즘을 아는 것보다 **조건을 빠짐없이 처리하는 능력**이다.

### 1.2 시간 복잡도부터 확인하기

완전 탐색이 가능할지 판단하려면 입력 크기를 먼저 확인해야 한다.

예를 들어 반복문이 세 개 중첩되어 있더라도 각 반복이 10번씩만 실행된다면 전체 연산량은 1,000번 정도다.

반대로 두 개의 반복문이라도 각각 100만 번 실행된다면 총 연산량은 매우 커진다.

| 시간 복잡도 | N이 100,000일 때 대략적인 연산 규모 |
|---|---:|
| O(log N) | 약 17 |
| O(N) | 100,000 |
| O(N log N) | 약 1,700,000 |
| O(N²) | 10,000,000,000 |

따라서 문제를 읽을 때는 입력 크기와 시간 제한을 함께 확인해야 한다.

실제 실행 시간은 언어, 연산 종류, 채점 환경에 따라 다르므로 단순한 연산 횟수만으로 통과 여부를 확정할 수는 없다.

### 1.3 방향 이동 구현

2차원 배열에서 방향에 따라 이동하는 문제가 자주 등장한다.

행과 열을 각각 `r`, `c`로 표현하면 다음처럼 이동할 수 있다.

| 방향 | 행 변화 | 열 변화 |
|---|---:|---:|
| 위 | -1 | 0 |
| 아래 | +1 | 0 |
| 왼쪽 | 0 | -1 |
| 오른쪽 | 0 | +1 |

이 규칙을 딕셔너리로 만들어 두면 코드가 간단해진다.

```python
moves = {
    "U": (-1, 0),
    "D": (1, 0),
    "L": (0, -1),
    "R": (0, 1),
}

def move_character(n, commands):
    r, c = 0, 0

    for command in commands:
        dr, dc = moves[command]

        nr = r + dr
        nc = c + dc

        if 0 <= nr < n and 0 <= nc < n:
            r, c = nr, nc

    return r, c


print(move_character(5, ["R", "R", "D", "L"]))
# (1, 1)
```

여기서 `nr`, `nc`는 이동한 다음의 좌표를 의미한다.

이동할 수 있는지 먼저 확인하고, 범위 안에 있을 때만 실제 위치를 갱신한다.

이 패턴은 미로, 게임 맵, 체스판, BFS 등에서도 반복적으로 사용된다.

### 1.4 완전 탐색은 언제 사용해도 될까?

가능한 경우의 수가 충분히 작다면 복잡하게 최적화하지 않아도 된다.

예를 들어 하루의 모든 시각을 초 단위로 확인해도 최대 86,400개뿐이다.

특정 숫자가 시각에 포함되는지 검사하려면 다음처럼 구현할 수 있다.

```python
def count_times(end_hour, digit):
    count = 0

    for h in range(end_hour + 1):
        for m in range(60):
            for s in range(60):
                time = f"{h:02d}:{m:02d}:{s:02d}"

                if str(digit) in time:
                    count += 1

    return count
```

가능한 모든 시각을 검사하므로 완전 탐색이다.

모든 경우를 확인하더라도 제한 시간 안에 처리할 수 있다면 충분히 좋은 방법이다.

### 1.5 구현 문제에서 자주 틀리는 부분

- 행과 열을 반대로 처리하는 실수
- 0부터 시작하는 인덱스와 1부터 시작하는 좌표를 혼동하는 실수
- 배열 범위를 벗어나는 경우를 처리하지 않는 실수
- 이미 방문한 위치를 다시 방문해도 되는지 확인하지 않는 실수
- 문제에 제시된 동작 순서를 잘못 구현하는 실수

특히 좌표를 사용할 때는 `x`, `y`보다 `row`, `col`이 더 명확할 때가 많다.

**복습 포인트:** 구현 문제에서는 먼저 상태, 이동 규칙, 예외 조건을 정리한 뒤 코드를 작성하자.

## 3. DFS와 BFS

### 2.1 탐색 알고리즘을 이해하기 전에

DFS와 BFS는 그래프를 탐색하는 대표적인 방법이다.

둘의 차이는 **어떤 노드를 먼저 방문하느냐**에 있다.

DFS는 한 방향으로 가능한 깊이 이동한다.

BFS는 시작점에서 가까운 노드부터 차례대로 방문한다.

이를 이해하려면 먼저 스택과 큐를 알아야 한다.

### 2.2 스택(Stack)

스택은 가장 나중에 넣은 데이터를 먼저 꺼내는 자료구조다.

이를 LIFO(Last In, First Out)라고 한다.

파이썬에서는 리스트만으로 구현할 수 있다.

```python
stack = []

stack.append("A")
stack.append("B")
stack.append("C")

print(stack.pop())  # C
print(stack.pop())  # B
```

가장 마지막에 넣은 C가 먼저 나온다.

재귀 함수 역시 호출이 쌓이고 반환되는 과정에서 스택과 유사하게 동작한다.

### 2.3 큐(Queue)

큐는 가장 먼저 넣은 데이터를 먼저 꺼내는 자료구조다.

이를 FIFO(First In, First Out)라고 한다.

파이썬에서는 `collections.deque`를 사용한다.

```python
from collections import deque

queue = deque()

queue.append("A")
queue.append("B")
queue.append("C")

print(queue.popleft())  # A
print(queue.popleft())  # B
```

리스트의 `pop(0)`은 뒤쪽 원소를 이동시키는 비용이 발생하므로, 앞에서 원소를 자주 꺼내야 하는 큐에는 `deque`가 적합하다.

### 2.4 DFS: 깊이 우선 탐색

DFS(Depth-First Search)는 한 경로를 따라 끝까지 탐색한 뒤, 더 이상 갈 곳이 없으면 이전 위치로 돌아와 다른 경로를 탐색한다.

예를 들어 다음과 같은 그래프가 있다고 하자.

```text
1 ─ 2 ─ 4
│
3 ─ 5
```

1번 노드에서 시작해 번호가 작은 인접 노드를 먼저 방문한다면 DFS는 다음 순서로 방문할 수 있다.

```text
1 → 2 → 4 → 3 → 5
```

DFS는 재귀 함수로 간단하게 구현할 수 있다.

```python
graph = {
    1: [2, 3],
    2: [1, 4],
    3: [1, 5],
    4: [2],
    5: [3],
}

visited = set()

def dfs(node):
    visited.add(node)
    print(node, end=" ")

    for next_node in graph[node]:
        if next_node not in visited:
            dfs(next_node)


dfs(1)
# 1 2 4 3 5
```

핵심은 방문 여부를 기록하는 `visited`다.

방문 처리를 하지 않으면 양방향 그래프에서 같은 노드를 계속 오갈 수 있다.

### 2.5 BFS: 너비 우선 탐색

BFS(Breadth-First Search)는 현재 노드와 가까운 노드부터 방문한다.

앞선 그래프에서 1번 노드부터 시작하면 다음과 같은 순서가 가능하다.

```text
1 → 2 → 3 → 4 → 5
```

BFS는 큐를 사용한다.

```python
from collections import deque

def bfs(start, graph):
    visited = {start}
    queue = deque([start])

    while queue:
        node = queue.popleft()
        print(node, end=" ")

        for next_node in graph[node]:
            if next_node not in visited:
                visited.add(next_node)
                queue.append(next_node)


bfs(1, graph)
# 1 2 3 4 5
```

BFS에서는 노드를 큐에 넣을 때 방문 처리하는 것이 중요하다.

꺼낼 때 방문 처리하면 동일한 노드가 큐에 중복으로 들어갈 수 있기 때문이다.

### 2.6 DFS와 BFS는 언제 사용할까?

| 구분 | DFS | BFS |
|---|---|---|
| 탐색 방향 | 한 경로를 깊게 탐색 | 가까운 노드부터 탐색 |
| 주로 사용하는 자료구조 | 스택, 재귀 | 큐 |
| 대표 문제 | 연결 요소, 경로 탐색, 백트래킹 | 최단 이동 횟수, 단계별 확산 |
| 주의점 | 재귀 깊이 | 방문 처리 시점 |

인접 리스트를 사용하는 일반적인 그래프 탐색의 시간 복잡도는 둘 다 `O(V+E)`다.

여기서 V는 정점 수, E는 간선 수다.

### 2.7 DFS 응용: 연결된 영역 세기

2차원 격자에서 값이 0인 칸끼리 상하좌우로 이어져 있다고 가정하자.

목표는 연결된 0의 영역이 몇 개인지 세는 것이다.

이런 문제는 **연결 요소(Connected Component)**를 세는 문제로 바꿔 생각할 수 있다.

```python
def count_areas(grid):
    n = len(grid)
    m = len(grid[0])

    visited = [[False] * m for _ in range(n)]
    directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

    def dfs(start_r, start_c):
        stack = [(start_r, start_c)]
        visited[start_r][start_c] = True

        while stack:
            r, c = stack.pop()

            for dr, dc in directions:
                nr, nc = r + dr, c + dc

                if not (0 <= nr < n and 0 <= nc < m):
                    continue

                if grid[nr][nc] != 0 or visited[nr][nc]:
                    continue

                visited[nr][nc] = True
                stack.append((nr, nc))

    count = 0

    for r in range(n):
        for c in range(m):
            if grid[r][c] == 0 and not visited[r][c]:
                dfs(r, c)
                count += 1

    return count
```

아직 방문하지 않은 0을 발견하면 그 위치에서 탐색을 시작한다.

연결된 모든 0이 방문 처리되므로 하나의 영역을 발견한 셈이다.

이후 다른 0을 발견하면 새로운 영역이므로 개수를 1 증가시킨다.

재귀 대신 명시적인 스택을 사용하면 큰 격자에서 재귀 깊이 초과 위험을 피할 수 있다.

### 2.8 BFS 응용: 미로의 최단 이동 횟수

BFS는 모든 이동의 비용이 동일할 때 최단 이동 횟수를 구하기 좋다.

시작점에서 한 칸 떨어진 위치를 먼저 탐색하고, 그다음 두 칸 떨어진 위치를 탐색하기 때문이다.

```python
from collections import deque

def shortest_path(grid):
    n = len(grid)
    m = len(grid[0])

    distance = [[-1] * m for _ in range(n)]
    distance[0][0] = 0

    queue = deque([(0, 0)])
    directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

    while queue:
        r, c = queue.popleft()

        for dr, dc in directions:
            nr, nc = r + dr, c + dc

            if not (0 <= nr < n and 0 <= nc < m):
                continue

            if grid[nr][nc] == 0:
                continue

            if distance[nr][nc] != -1:
                continue

            distance[nr][nc] = distance[r][c] + 1
            queue.append((nr, nc))

    return distance[n - 1][m - 1]
```

이 코드는 시작 칸의 거리를 0으로 정의한 **이동 횟수**를 반환한다.

시작 칸까지 포함한 방문 칸 수가 필요하다면 정답에 1을 더하는 등 문제의 기준에 맞춰야 한다.

**복습 포인트:** 연결된 영역을 전부 탐색할 때는 DFS/BFS를, 모든 간선 비용이 동일한 최단 경로를 구할 때는 BFS를 먼저 고려하자.

## 4. 정렬(Sorting)

### 3.1 정렬이 중요한 이유

정렬은 데이터를 특정한 기준에 맞게 나열하는 작업이다.

정렬이 되어 있으면 데이터의 순서를 활용하여 탐색을 빠르게 하거나, 가장 작거나 큰 값을 쉽게 선택할 수 있다.

코딩테스트에서는 정렬 알고리즘의 구현을 직접 요구하기도 하지만, 실제로는 **어떤 기준으로 정렬해야 하는지** 판단하는 문제가 많다.

### 3.2 선택 정렬(Selection Sort)

선택 정렬은 정렬되지 않은 구간에서 가장 작은 값을 찾아 앞쪽으로 옮기는 알고리즘이다.

예를 들어 다음 데이터가 있다고 하자.

```text
[7, 3, 9, 2]
```

첫 번째 단계에서 최솟값 2를 찾아 맨 앞의 7과 교환한다.

```text
[2, 3, 9, 7]
```

두 번째 단계에서는 남은 구간에서 최솟값을 찾아 두 번째 위치에 놓는다.

이 과정을 반복하면 전체 데이터가 정렬된다.

```python
def selection_sort(arr):
    n = len(arr)

    for i in range(n):
        min_idx = i

        for j in range(i + 1, n):
            if arr[j] < arr[min_idx]:
                min_idx = j

        arr[i], arr[min_idx] = arr[min_idx], arr[i]

    return arr
```

시간 복잡도는 `O(N²)`이다.

이미 정렬되어 있어도 남은 원소를 계속 비교해야 한다.

### 3.3 삽입 정렬(Insertion Sort)

삽입 정렬은 앞부분이 이미 정렬되어 있다고 가정하고, 새로운 값을 적절한 위치에 끼워 넣는다.

예를 들어 다음 배열을 생각해 보자.

```text
[2, 5, 8, 4]
```

앞의 `[2, 5, 8]`은 정렬되어 있다.

마지막 값 4를 삽입하려면 8과 5를 오른쪽으로 한 칸씩 밀어야 한다.

```text
[2, 4, 5, 8]
```

```python
def insertion_sort(arr):
    for i in range(1, len(arr)):
        value = arr[i]
        j = i - 1

        while j >= 0 and arr[j] > value:
            arr[j + 1] = arr[j]
            j -= 1

        arr[j + 1] = value

    return arr
```

평균과 최악의 시간 복잡도는 `O(N²)`이지만, 이미 정렬된 경우에는 `O(N)`으로 동작할 수 있다.

따라서 데이터가 거의 정렬되어 있다면 효율적일 수 있다.

### 3.4 퀵 정렬(Quick Sort)

퀵 정렬은 기준값인 피벗(Pivot)을 선택하고, 피벗보다 작은 값과 큰 값으로 데이터를 분할한다.

이후 나누어진 부분에 같은 과정을 반복한다.

예를 들어 피벗을 5로 정했다면 다음과 같이 나눌 수 있다.

```text
원본: [5, 9, 2, 7, 3]

작은 값: [2, 3]
피벗: 5
큰 값: [9, 7]
```

각 부분을 다시 정렬하면 전체 배열이 정렬된다.

원리를 이해하기 위한 간단한 구현은 다음과 같다.

```python
def quick_sort(arr):
    if len(arr) <= 1:
        return arr

    pivot = arr[0]

    left = [x for x in arr[1:] if x <= pivot]
    right = [x for x in arr[1:] if x > pivot]

    return quick_sort(left) + [pivot] + quick_sort(right)
```

평균 시간 복잡도는 `O(N log N)`이다.

하지만 피벗이 한쪽으로 치우쳐 분할되면 최악의 경우 `O(N²)`이 될 수 있다.

위 코드는 분할 원리를 보여주기 위한 예제이며, 추가 리스트를 생성하므로 제자리 정렬 방식과는 공간 사용량이 다르다.

### 3.5 계수 정렬(Counting Sort)

계수 정렬은 원소를 직접 비교하는 대신 **각 값이 몇 번 등장하는지 세는 방식**이다.

예를 들어 다음과 같은 데이터가 있다고 하자.

```text
[3, 1, 2, 3, 1, 3]
```

각 숫자의 등장 횟수를 세면 다음과 같다.

| 값 | 등장 횟수 |
|---|---:|
| 1 | 2 |
| 2 | 1 |
| 3 | 3 |

이제 값 1을 두 번, 2를 한 번, 3을 세 번 출력하면 정렬이 끝난다.

```python
def counting_sort(arr):
    if not arr:
        return []

    minimum = min(arr)
    maximum = max(arr)

    counts = [0] * (maximum - minimum + 1)

    for value in arr:
        counts[value - minimum] += 1

    result = []

    for idx, count in enumerate(counts):
        value = idx + minimum
        result.extend([value] * count)

    return result
```

원소 개수가 N개이고 값의 범위 크기가 R이면 시간 복잡도는 `O(N+R)`이다.

빈도 배열은 `O(R)` 공간을 사용하고, 위 구현은 정렬 결과를 별도 리스트로 생성하므로 총 추가 공간은 `O(N+R)`이다.

계수 정렬은 값의 범위가 좁은 정수 데이터에 적합하다.

예를 들어 원소가 `[1, 1_000_000_000]` 두 개뿐이라면 거대한 빈도 배열이 필요하므로 비효율적이다.

### 3.6 파이썬의 정렬 기능

실전에서는 대부분 직접 정렬 알고리즘을 구현하기보다 `sorted()` 또는 `.sort()`를 사용한다.

```python
numbers = [5, 1, 9, 3]

a = sorted(numbers)
print(a)  # [1, 3, 5, 9]

numbers.sort(reverse=True)
print(numbers)  # [9, 5, 3, 1]
```

- `sorted()`는 정렬된 새 리스트를 반환한다.
- `.sort()`는 기존 리스트를 직접 정렬한다.

파이썬 정렬은 Timsort 기반이며 안정 정렬(Stable Sort)이다.

일반적인 최악의 시간 복잡도는 `O(N log N)`이다.

여러 조건에 따른 정렬에는 `key`를 활용한다.

```python
students = [
    ("민수", 85),
    ("지연", 95),
    ("서준", 85),
]

students.sort(key=lambda x: (-x[1], x[0]))

print(students)
```

이 코드는 점수가 높은 순서대로 정렬하고, 점수가 같다면 이름을 오름차순으로 정렬한다.

**복습 포인트:** 실전에서는 기본 정렬을 우선 사용하고, 데이터의 범위가 좁은 정수라면 계수 정렬을 검토하자.

## 5. 이진 탐색(Binary Search)

### 4.1 순차 탐색과 이진 탐색

순차 탐색은 배열의 처음부터 끝까지 하나씩 확인한다.

```python
def linear_search(arr, target):
    for idx, value in enumerate(arr):
        if value == target:
            return idx

    return -1
```

최악의 시간 복잡도는 `O(N)`이다.

반면 이진 탐색은 정렬된 데이터에서 중간값을 확인하고 탐색 범위를 절반씩 줄인다.

시간 복잡도는 `O(log N)`이다.

### 4.2 직접 구현하기

```python
def binary_search(arr, target):
    left = 0
    right = len(arr) - 1

    while left <= right:
        mid = (left + right) // 2

        if arr[mid] == target:
            return mid

        if arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1

    return -1
```

가장 중요한 부분은 범위를 줄이는 코드다.

`arr[mid] < target`이면 목표값이 오른쪽에 있으므로 `left = mid + 1`로 이동한다.

반대로 목표값이 작으면 왼쪽 절반을 탐색한다.

중앙 위치를 이미 확인했으므로 다음 범위에서 `mid`를 제외해야 무한 반복을 막을 수 있다.

### 4.3 재귀로 구현하기

```python
def binary_search_recursive(arr, target, left, right):
    if left > right:
        return -1

    mid = (left + right) // 2

    if arr[mid] == target:
        return mid

    if arr[mid] < target:
        return binary_search_recursive(
            arr, target, mid + 1, right
        )

    return binary_search_recursive(
        arr, target, left, mid - 1
    )
```

재귀와 반복문 모두 시간 복잡도는 `O(log N)`이다.

반복문은 추가 호출 스택을 사용하지 않으므로 공간 측면에서 유리하다.

### 4.4 이진 탐색은 값뿐 아니라 경계도 찾는다

정렬된 배열에서 특정 값의 등장 횟수를 구할 때는 값 하나를 찾는 것으로 충분하지 않다.

값이 시작되는 경계와 끝나는 경계를 찾아야 한다.

```python
from bisect import bisect_left, bisect_right

arr = [1, 2, 2, 2, 5, 7]

left = bisect_left(arr, 2)
right = bisect_right(arr, 2)

print(right - left)  # 3
```

`bisect_left`는 값 이상이 처음 나타나는 위치를, `bisect_right`는 값 초과가 처음 나타나는 위치를 찾는다.

또한 특정 조건이 처음으로 참이 되는 지점처럼 **정답의 경계가 단조롭게 변하는 문제**에서도 이진 탐색을 활용할 수 있다.

### 4.5 이진 탐색 트리(BST)

이진 탐색 트리는 일반적인 배열 이진 탐색과 다른 자료구조다.

각 노드는 최대 두 개의 자식 노드를 가지며 다음 순서 관계를 만족한다.

```text
왼쪽 서브트리의 값 < 현재 노드의 값 < 오른쪽 서브트리의 값
```

예를 들어 다음과 같은 트리를 생각해 보자.

```text
       10
      /  \
     5    15
    / \     \
   2   7     20
```

7을 찾을 때는 10보다 작으므로 왼쪽으로 이동한다.

다음 노드 5보다 크므로 오른쪽으로 이동하면 7을 찾을 수 있다.

트리 높이가 균형 있게 유지되면 탐색이 `O(log N)`이지만, 한쪽으로 치우친 트리는 최악의 경우 `O(N)`이 된다.

또한 **이진 탐색 트리와 힙은 서로 다른 구조**다. 힙은 부모와 자식 간 우선순위를 유지하지만, BST처럼 왼쪽과 오른쪽 서브트리 전체의 정렬 관계를 유지하지는 않는다.

### 4.6 빠른 입력 처리

입력량이 많을 때는 `sys.stdin.readline`을 사용할 수 있다.

```python
import sys

input = sys.stdin.readline

n = int(input())
numbers = list(map(int, input().split()))
```

`readline()`으로 읽은 문자열에는 보통 마지막 개행 문자가 포함된다.

다만 `int()`나 `split()`처럼 공백을 자체적으로 처리하는 경우에는 매번 `rstrip()`을 호출할 필요가 없다.

문자열의 마지막 개행 문자를 정확히 제거해야 할 때 사용하면 된다.

**복습 포인트:** 이진 탐색 문제에서는 정렬 여부와 함께, 어느 조건에서 탐색 구간의 절반을 버릴 수 있는지 확인하자.

### 5.7 이진 탐색의 기본 원리 다시 보기

#### 이진 탐색이란?

이진 탐색은 정렬된 데이터에서 탐색 범위를 절반씩 줄여 원하는 값을 찾는 방법이다.

예를 들어 숫자가 100만 개 있어도 매번 절반을 버리기 때문에 적은 횟수로 탐색할 수 있다.

가장 중요한 전제는 **탐색 범위를 버려도 정답이 남아 있다는 사실을 판단할 수 있어야 한다**는 것이다.

일반적인 배열 탐색에서는 데이터가 정렬되어 있어야 이 판단이 가능하다.

#### 기본 원리

다음과 같은 정렬된 배열이 있다고 하자.

```python
arr = [2, 5, 8, 11, 14, 17, 20]
target = 14
```

처음에는 배열의 중앙 값인 11을 확인한다.

14는 11보다 크므로 11 이하의 값은 확인할 필요가 없다.

따라서 오른쪽 절반에서 다시 중앙 값을 찾는다.

이 과정을 반복하면서 정답을 찾는다.

#### 기본 Python 구현

```python
def binary_search(arr, target):
    left = 0
    right = len(arr) - 1

    while left <= right:
        mid = (left + right) // 2

        if arr[mid] == target:
            return mid

        if arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1

    return -1
```

시간 복잡도는 `O(log N)`이다.

#### 이진 탐색에서 자주 실수하는 부분

- `left <= right`와 `left < right`의 차이를 이해해야 한다.
- 중앙값을 확인한 후에는 `mid + 1` 또는 `mid - 1`로 범위를 확실히 줄여야 한다.
- 정렬되어 있지 않은 배열에 일반적인 이진 탐색을 적용할 수 없다.
- 중복된 값이 있다면 일반 이진 탐색이 처음 또는 마지막 위치를 반환한다는 보장은 없다.

---

### 5.8 이진 탐색 예제 ① 특정 숫자의 등장 횟수

#### 핵심 상황

정렬된 배열에 같은 숫자가 여러 번 등장한다.

이때 특정 숫자가 몇 번 등장하는지 알고 싶다.

```python
arr = [1, 2, 2, 2, 4, 4, 7, 9]
target = 2
```

정답은 3이다.

하지만 배열이 매우 크다면 전체를 순회하는 `count()`는 시간 제한에 걸릴 수 있다.

이럴 때는 숫자가 처음 나타나는 위치와 마지막으로 나타난 위치를 이용하면 된다.

#### Lower Bound와 Upper Bound

**Lower Bound**는 대상 값 이상이 처음 나타나는 위치다.

**Upper Bound**는 대상 값보다 큰 값이 처음 나타나는 위치다.

배열에서 값 2를 기준으로 생각해 보자.

```text
값:      1  2  2  2  4  4  7  9
인덱스:  0  1  2  3  4  5  6  7

Lower Bound = 1
Upper Bound = 4
```

따라서 등장 횟수는 `4 - 1 = 3`이다.

#### Python 구현

Python의 `bisect` 모듈을 사용하면 간단하게 구현할 수 있다.

```python
from bisect import bisect_left, bisect_right

def count_target(arr, target):
    left = bisect_left(arr, target)
    right = bisect_right(arr, target)

    count = right - left
    return count if count > 0 else -1


arr = [1, 2, 2, 2, 4, 4, 7, 9]

print(count_target(arr, 2))   # 3
print(count_target(arr, 5))   # -1
```

`bisect_left`와 `bisect_right`는 각각 이진 탐색으로 위치를 찾는다.

따라서 시간 복잡도는 `O(log N)`이다.

#### 꼭 기억할 것

중복된 숫자를 다루는 이진 탐색 문제에서는 단순히 숫자를 찾는 것보다 **경계 위치를 찾는 것**이 중요할 수 있다.

**복습 포인트:** 정렬된 배열에서 특정 값의 개수를 구하라고 하면 `bisect_right - bisect_left`를 떠올리자.

### 5.9 이진 탐색 예제 ② 고정점 찾기

#### 고정점이란?

배열의 값과 인덱스가 같은 위치를 고정점이라고 한다.

예를 들어 다음 배열을 보자.

```python
arr = [-8, -2, 2, 5, 10]
```

인덱스 2의 값이 2이므로 고정점은 2다.

일반적인 방법은 모든 위치를 확인하는 것이다.

하지만 배열이 오름차순이고 모든 원소가 서로 다르다면 이진 탐색을 사용할 수 있다.

#### 왜 이진 탐색이 가능할까?

배열이 엄격하게 증가한다는 조건을 이용할 수 있기 때문이다.

중앙 위치에서 `arr[mid]`와 `mid`를 비교한다.

- `arr[mid] == mid`: 고정점을 찾았다.
- `arr[mid] < mid`: 고정점이 있다면 오른쪽에 있어야 한다.
- `arr[mid] > mid`: 고정점이 있다면 왼쪽에 있어야 한다.

예를 들어 인덱스 3에서 값이 5라면, 그보다 오른쪽의 값은 인덱스 증가 속도보다 작게 증가하지 않는다.

따라서 오른쪽에서 고정점을 찾을 수 없다.

이 성질을 이용해 절반의 구간을 버릴 수 있다.

#### Python 구현

```python
def find_fixed_point(arr):
    left = 0
    right = len(arr) - 1

    while left <= right:
        mid = (left + right) // 2

        if arr[mid] == mid:
            return mid

        if arr[mid] < mid:
            left = mid + 1
        else:
            right = mid - 1

    return -1


print(find_fixed_point([-8, -2, 2, 5, 10]))  # 2
```

시간 복잡도는 `O(log N)`이다.

#### 주의할 점

이 방법은 배열이 정렬되어 있고 **중복 원소가 없다는 조건**에 의존한다.

중복이 허용되면 `arr[mid]`와 `mid`의 비교만으로 한쪽 구간에 정답이 없다고 단정할 수 없다.

**복습 포인트:** 이진 탐색은 특정 숫자를 찾는 것뿐 아니라, 조건을 비교하여 탐색 범위를 줄일 수 있는 문제에도 활용된다.

## 6. 다이나믹 프로그래밍(Dynamic Programming)

### 5.1 DP는 왜 필요할까?

어떤 문제는 작은 문제를 여러 번 반복해서 계산하기 때문에 실행 시간이 크게 증가한다.

다이나믹 프로그래밍(DP)은 이러한 중복 계산을 줄이기 위한 기법이다.

핵심은 다음과 같다.

**이미 계산한 문제의 결과를 저장해 두고, 같은 문제가 다시 등장하면 계산하지 않고 가져온다.**

일반적으로 DP를 적용할 때는 두 가지를 살펴본다.

- **최적 부분 구조:** 작은 문제의 답을 활용해 큰 문제의 답을 구성할 수 있는가?
- **중복되는 부분 문제:** 동일한 작은 문제를 여러 번 계산하는가?

### 5.2 피보나치 수열로 이해하기

피보나치 수열은 앞의 두 항을 더해 다음 항을 만드는 수열이다.

$$
F(n)=F(n-1)+F(n-2)
$$

초깃값은 다음과 같다.

$$
F(1)=F(2)=1
$$

이를 그대로 재귀 함수로 구현할 수 있다.

```python
def fibo(n):
    if n <= 2:
        return 1

    return fibo(n - 1) + fibo(n - 2)
```

문제는 같은 항을 반복해서 계산한다는 것이다.

예를 들어 `fibo(5)`를 구할 때 `fibo(3)`은 여러 번 호출된다.

N이 커질수록 호출 수가 급격히 증가하며 지수 시간 복잡도를 가진다.

### 5.3 Top-Down: 메모이제이션

Top-Down은 큰 문제에서 시작해 필요한 작은 문제를 재귀적으로 해결하는 방식이다.

여기에 메모이제이션을 적용하면 이미 계산한 값을 다시 계산하지 않아도 된다.

```python
def fibonacci(n):
    memo = {}

    def solve(x):
        if x <= 2:
            return 1

        if x in memo:
            return memo[x]

        memo[x] = solve(x - 1) + solve(x - 2)

        return memo[x]

    return solve(n)
```

여기서 `memo`는 이미 계산한 결과를 저장하는 딕셔너리다.

각 항을 한 번씩만 계산하므로 시간 복잡도는 `O(N)`이다.

메모이제이션은 재귀와 자주 함께 사용되지만, 본질적으로는 계산 결과를 기억해 재사용하는 기법이다.

### 5.4 Bottom-Up: DP 테이블

Bottom-Up은 가장 작은 문제부터 차례대로 계산한다.

```python
def fibonacci(n):
    if n <= 2:
        return 1

    dp = [0] * (n + 1)

    dp[1] = 1
    dp[2] = 1

    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]

    return dp[n]
```

재귀 함수 대신 반복문을 사용한다.

일반적으로 재귀 호출 비용과 호출 깊이 제한을 피할 수 있어 Python에서는 Bottom-Up을 우선 고려하기 좋다.

### 5.5 메모리 최적화

피보나치 수열에서 현재 항을 계산할 때 필요한 값은 이전 두 항뿐이다.

따라서 모든 항을 리스트에 저장할 필요가 없다.

```python
def fibonacci(n):
    if n <= 2:
        return 1

    a, b = 1, 1

    for _ in range(3, n + 1):
        a, b = b, a + b

    return b
```

이 방법은 `O(N)`의 시간으로 계산하면서 추가 공간을 `O(1)`만 사용한다.

### 5.6 DP와 분할 정복의 차이

둘 다 큰 문제를 작은 문제로 나눌 수 있다.

하지만 핵심적인 차이는 작은 문제의 **중복 여부**다.

퀵 정렬과 같은 분할 정복에서는 일반적으로 분할된 부분 문제를 각각 처리한다.

반면 DP에서는 동일한 부분 문제가 여러 경로에서 다시 필요할 수 있다.

이때 이미 구한 결과를 재사용하면 효율적으로 해결할 수 있다.

### 5.7 DP 문제를 푸는 순서

DP를 처음 접했을 때는 점화식을 세우는 것이 어렵다.

따라서 다음 순서로 접근하면 좋다.

1. `dp[i]`가 무엇을 의미하는지 정의한다.
2. 가장 작은 문제의 정답을 정한다.
3. 큰 문제의 정답이 작은 문제와 어떻게 연결되는지 찾는다.
4. 점화식을 작성한다.
5. Top-Down 또는 Bottom-Up으로 구현한다.

예를 들어 한 번에 1칸 또는 2칸씩 계단을 올라가는 경우의 수를 계산한다고 하자.

마지막에 1칸을 올라왔다면 직전 위치는 `i-1`이다.

마지막에 2칸을 올라왔다면 직전 위치는 `i-2`다.

따라서 다음 점화식이 성립한다.

$$
dp[i]=dp[i-1]+dp[i-2]
$$

단, 실제 계단 문제에서는 이동 제약이나 점수 조건에 따라 점화식이 달라질 수 있다.

**복습 포인트:** DP가 떠오르지 않을 때는 먼저 완전 탐색이나 재귀로 문제를 나눈 뒤, 같은 계산을 반복하는지 살펴보자.

## 7. 최단 경로(Shortest Path)

### 6.1 최단 경로 문제란?

그래프에서 한 노드에서 다른 노드까지 이동하는 최소 비용을 구하는 문제다.

예를 들어 도시간 도로 비용이 주어졌을 때 가장 적은 비용으로 목적지까지 이동하는 경로를 찾는 상황이다.

대표적으로 다음 두 알고리즘을 기억하자.

| 알고리즘 | 주로 해결하는 문제 | 시간 복잡도 |
|---|---|---|
| 다익스트라 | 하나의 출발점에서 다른 노드들까지 | 힙 사용 시 일반적으로 O((V+E) log V) |
| 플로이드 워셜 | 모든 노드 쌍 사이의 최단 거리 | O(V³) |

### 6.2 다익스트라(Dijkstra)

다익스트라는 하나의 시작점에서 다른 노드들까지의 최단 거리를 구한다.

단, 일반적인 다익스트라는 **음수 간선이 없는 그래프**에서 사용해야 한다.

핵심 아이디어는 현재까지 확인한 거리 중 가장 짧은 노드를 먼저 처리하는 것이다.

예를 들어 다음과 같은 경로가 있다고 하자.

```text
A → B : 비용 4
A → C : 비용 2
C → B : 비용 1
```

A에서 B까지 직접 이동하면 비용이 4다.

하지만 C를 경유하면 비용이 `2 + 1 = 3`이다.

따라서 B까지의 최단 거리를 4에서 3으로 갱신할 수 있다.

이처럼 더 짧은 경로를 발견하면 거리 테이블을 갱신하는 과정을 **Relaxation(완화)**이라고 한다.

### 6.3 우선순위 큐를 이용한 다익스트라

모든 노드 중 최단 거리가 가장 작은 노드를 매번 직접 찾는다면 비효율적이다.

따라서 최소 힙을 활용하면 더 빠르게 처리할 수 있다.

```python
import heapq

def dijkstra(graph, start):
    INF = float("inf")

    distance = {
        node: INF for node in graph
    }
    distance[start] = 0

    heap = [(0, start)]

    while heap:
        current_dist, node = heapq.heappop(heap)

        if current_dist > distance[node]:
            continue

        for next_node, weight in graph[node]:
            new_dist = current_dist + weight

            if new_dist < distance[next_node]:
                distance[next_node] = new_dist

                heapq.heappush(
                    heap, (new_dist, next_node)
                )

    return distance
```

사용 예시는 다음과 같다.

```python
graph = {
    "A": [("B", 4), ("C", 2)],
    "B": [("D", 3)],
    "C": [("B", 1), ("D", 7)],
    "D": [],
}

print(dijkstra(graph, "A"))
# {'A': 0, 'B': 3, 'C': 2, 'D': 6}
```

여기서 반드시 이해해야 하는 코드는 다음 부분이다.

```python
if current_dist > distance[node]:
    continue
```

힙에는 같은 노드에 대한 거리 정보가 여러 번 들어갈 수 있다.

예를 들어 B까지의 거리가 처음에는 4로 기록되었다가 나중에 3으로 갱신될 수 있다.

이때 예전 정보인 `(4, B)`가 힙에서 나오면 이미 더 짧은 경로가 있으므로 무시한다.

### 6.4 플로이드 워셜(Floyd-Warshall)

플로이드 워셜은 **모든 출발점에서 모든 도착점까지의 최단 거리**를 구하는 알고리즘이다.

다익스트라와 달리 2차원 거리 테이블을 사용한다.

핵심은 특정 노드 K를 거쳐 이동하는 경로가 기존 경로보다 더 짧은지 확인하는 것이다.

$$
D[i][j]
=
\min(D[i][j],D[i][k]+D[k][j])
$$

예를 들어 A에서 C로 직접 이동하는 비용이 10이라고 하자.

A에서 B로 이동하는 비용이 3이고 B에서 C로 이동하는 비용이 4라면 B를 경유하는 비용은 7이다.

따라서 A에서 C까지의 거리를 10에서 7로 갱신한다.

```python
def floyd_warshall(n, edges):
    INF = float("inf")

    dist = [[INF] * n for _ in range(n)]

    for i in range(n):
        dist[i][i] = 0

    for a, b, cost in edges:
        dist[a][b] = min(dist[a][b], cost)

    for k in range(n):
        for i in range(n):
            for j in range(n):
                dist[i][j] = min(
                    dist[i][j],
                    dist[i][k] + dist[k][j]
                )

    return dist
```

이 코드에서 가장 바깥쪽 반복문은 `k`다.

**K를 경유하는 경로를 허용하면서 거리 테이블을 갱신한다**는 것이 알고리즘의 핵심이기 때문이다.

시간 복잡도는 `O(V³)`, 공간 복잡도는 `O(V²)`다.

음수 간선이 있어도 음수 사이클이 없다면 최단 거리를 구할 수 있다.

### 6.5 다익스트라와 플로이드 워셜의 선택 기준

다익스트라는 한 출발점에서 여러 노드까지의 거리가 필요할 때 적합하다.

플로이드 워셜은 모든 노드 쌍의 거리를 알아야 하고, 노드 수가 비교적 적을 때 유용하다.

다익스트라의 힙은 현재 가장 작은 거리를 빠르게 선택하기 위해 사용한다.

반면 플로이드 워셜은 모든 중간 경유지를 하나씩 허용해 가며 테이블을 갱신한다.

**복습 포인트:** 출발점이 하나인지, 모든 노드 쌍인지부터 확인하자. 음수 간선 여부도 반드시 살펴봐야 한다.

## 8. 그래프 이론(Graph Theory)

### 7.1 그래프의 기본 구조

그래프는 정점(Vertex)과 간선(Edge)으로 구성된다.

예를 들어 도시를 정점으로, 도로를 간선으로 표현할 수 있다.

그래프는 방향이 있을 수도 있고 없을 수도 있으며, 사이클이 존재할 수도 있다.

트리는 사이클이 없는 연결 그래프다.

일반적인 루트 트리는 특정 노드를 루트로 정하여 부모와 자식 관계를 부여한 구조다.

### 7.2 인접 행렬과 인접 리스트

그래프를 저장하는 대표적인 방법은 두 가지다.

**인접 행렬**은 모든 노드 쌍의 연결 관계를 2차원 배열에 저장한다.

```python
graph = [
    [0, 1, 0],
    [1, 0, 1],
    [0, 1, 0],
]
```

특정 두 노드 사이에 간선이 있는지 `O(1)`에 확인할 수 있다.

하지만 노드 수가 V개라면 `O(V²)`의 공간이 필요하다.

**인접 리스트**는 연결된 노드의 정보만 저장한다.

```python
graph = [
    [1],
    [0, 2],
    [1],
]
```

전체 공간은 일반적으로 `O(V+E)`가 필요하다.

특정 노드의 이웃만 순회하면 되므로 간선이 적은 희소 그래프에서 유리하다.

### 7.3 서로소 집합(Disjoint Set)

서로소 집합 자료구조는 여러 원소가 어떤 그룹에 속하는지를 관리하는 자료구조다.

대표적인 연산은 두 가지다.

- `find(x)`: x가 속한 집합의 대표 원소를 찾는다.
- `union(a, b)`: a와 b가 속한 두 집합을 합친다.

예를 들어 1과 2를 연결하고, 2와 3을 연결한다면 1, 2, 3은 하나의 집합에 속한다.

### 7.4 Union-Find 구현

```python
class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])

        return self.parent[x]

    def union(self, a, b):
        root_a = self.find(a)
        root_b = self.find(b)

        if root_a == root_b:
            return False

        if self.size[root_a] < self.size[root_b]:
            root_a, root_b = root_b, root_a

        self.parent[root_b] = root_a
        self.size[root_a] += self.size[root_b]

        return True
```

사용 예시는 다음과 같다.

```python
uf = UnionFind(6)

uf.union(1, 2)
uf.union(2, 3)
uf.union(4, 5)

print(uf.find(1) == uf.find(3))  # True
print(uf.find(1) == uf.find(5))  # False
```

`find()`에는 경로 압축(Path Compression)을 적용했다.

대표 원소를 찾는 과정에서 방문한 노드들이 직접 루트를 가리키도록 만들어 이후 탐색을 빠르게 한다.

또한 `union()`에는 집합 크기 기반 병합을 적용했다.

작은 집합을 큰 집합에 붙여 트리가 지나치게 깊어지지 않도록 한다.

이 두 최적화를 함께 사용하면 연산의 분할 상환 시간 복잡도는 거의 상수 시간인 `O(α(N))`이다.

### 7.5 사이클 판별

무방향 그래프에서 Union-Find를 활용하면 간선을 추가할 때 사이클이 생기는지 판단할 수 있다.

어떤 간선 `(a, b)`를 추가하려고 할 때 두 노드가 이미 같은 집합에 속한다면, 해당 간선을 추가하면 사이클이 만들어진다.

```python
uf = UnionFind(5)

edges = [(0, 1), (1, 2), (2, 0)]

for a, b in edges:
    if not uf.union(a, b):
        print("사이클 발견")
        break
```

첫 번째와 두 번째 간선으로 0, 1, 2가 이미 연결된다.

따라서 마지막 간선 `(2, 0)`을 추가하면 사이클이 된다.

### 7.6 크루스칼(Kruskal) 알고리즘

크루스칼은 모든 노드를 연결하면서 간선 비용의 합이 최소가 되는 최소 신장 트리(MST)를 구하는 알고리즘이다.

기본 전략은 다음과 같다.

1. 간선을 비용이 작은 순서대로 정렬한다.
2. 사이클을 만들지 않는 간선을 선택한다.
3. 모든 노드가 연결될 때까지 반복한다.

여기서 사이클 여부를 판단하는 데 Union-Find를 사용한다.

```python
def kruskal(n, edges):
    uf = UnionFind(n)
    total = 0
    selected = 0

    for cost, a, b in sorted(edges):
        if uf.union(a, b):
            total += cost
            selected += 1

            if selected == n - 1:
                break

    if selected != n - 1:
        return None

    return total
```

연결 그래프라면 N개의 노드를 연결하는 신장 트리에는 N-1개의 간선이 필요하다.

시간 복잡도는 간선 정렬이 지배하므로 일반적으로 `O(E log E)`다.

### 7.7 위상 정렬(Topological Sort)

위상 정렬은 선후 관계가 존재하는 작업들을 순서대로 배치하는 알고리즘이다.

예를 들어 다음 작업이 있다고 하자.

```text
기획 → 개발 → 테스트 → 배포
```

개발을 완료하지 않고 테스트를 진행할 수 없는 것처럼 일부 작업에는 순서가 필요하다.

이런 관계를 방향 그래프로 표현하고, 사이클이 없는 경우 위상 정렬을 수행할 수 있다.

대표적인 방법은 진입 차수(Indegree)가 0인 노드부터 처리하는 것이다.

```python
from collections import deque

def topological_sort(n, edges):
    graph = [[] for _ in range(n)]
    indegree = [0] * n

    for a, b in edges:
        graph[a].append(b)
        indegree[b] += 1

    queue = deque(
        i for i in range(n) if indegree[i] == 0
    )

    result = []

    while queue:
        node = queue.popleft()
        result.append(node)

        for next_node in graph[node]:
            indegree[next_node] -= 1

            if indegree[next_node] == 0:
                queue.append(next_node)

    if len(result) != n:
        return None  # 사이클 존재

    return result
```

모든 노드를 처리하지 못했다면 선후 관계에 사이클이 존재한다는 뜻이다.

시간 복잡도는 `O(V+E)`다.

**복습 포인트:** 집합을 합치고 연결 관계를 판별할 때는 Union-Find, 최소 비용으로 전체를 연결할 때는 크루스칼, 작업의 선후 관계를 정렬할 때는 위상 정렬을 떠올리자.

## 9. 알고리즘 비교와 복습 질문

### 9.1 그리디와 이진 탐색 비교

| 구분 | 그리디 | 이진 탐색 |
|---|---|---|
| 핵심 아이디어 | 현재 가장 유리한 선택 반복 | 탐색 범위를 절반씩 줄이기 |
| 가장 중요한 조건 | 지역적 선택이 최적해로 이어져야 함 | 한쪽 구간을 버릴 근거가 있어야 함 |
| 주요 실수 | 그리디가 통하지 않는 반례를 놓침 | 경계값과 인덱스 처리 오류 |
| 자주 함께 쓰는 개념 | 정렬, 우선순위 | 정렬, 경계 탐색 |
| 대표 시간 복잡도 | 문제에 따라 다름 | O(log N) |

두 알고리즘은 접근 방식이 다르지만 공통점이 있다.

**불필요한 경우의 수를 계산하지 않는다는 것**이다.

그리디는 선택을 확정하면서 경우의 수를 줄이고, 이진 탐색은 불필요한 탐색 구간을 제거한다.

따라서 코딩테스트를 풀 때는 무조건 모든 경우를 탐색하기보다, 어떤 선택이나 구간을 안전하게 제외할 수 있는지 고민해 보는 것이 좋다.

### 9.2 그리디·이진 탐색 복습 질문

### 그리디

- 지금 가장 유리한 선택을 반복해도 최적해가 되는 이유는 무엇인가?
- 반례를 만들 수 있는가?
- 정렬이 필요한가?
- 반복되는 선택을 수식으로 줄일 수 있는가?
- 그리디로 해결할 수 없다면 DP가 필요한 구조인가?

### 이진 탐색

- 데이터가 정렬되어 있는가?
- 중앙값을 비교했을 때 어느 구간을 버릴 수 있는가?
- 찾는 것이 값 자체인가, 조건을 만족하는 경계인가?
- `left`, `right`, `mid`가 어떤 범위를 나타내는가?
- 중복 원소나 정답이 없는 경우도 처리했는가?

### 9.3 전체 알고리즘 선택 기준

| 문제의 특징 | 먼저 떠올릴 알고리즘 |
|---|---|
| 정해진 규칙대로 캐릭터가 이동한다 | 구현, 시뮬레이션 |
| 경우의 수가 적어 모두 검사할 수 있다 | 완전 탐색 |
| 연결된 영역의 개수를 센다 | DFS 또는 BFS |
| 이동 비용이 동일하고 최단 이동 횟수를 구한다 | BFS |
| 데이터를 기준에 맞게 나열한다 | 정렬 |
| 정렬된 배열에서 빠르게 값을 찾는다 | 이진 탐색 |
| 동일한 작은 문제가 반복된다 | DP |
| 하나의 시작점에서 최단 거리를 구한다 | 다익스트라 |
| 모든 노드 쌍의 최단 거리를 구한다 | 플로이드 워셜 |
| 두 원소가 같은 집합에 속하는지 확인한다 | Union-Find |
| 모든 노드를 최소 비용으로 연결한다 | 크루스칼 |
| 작업의 선후 관계를 정리한다 | 위상 정렬 |

### 9.4 핵심 암기 노트

### 구현

문제에서 요구한 조건을 정확하게 코드로 옮기는 것이 핵심이다. 좌표, 범위, 방향, 예외 처리를 꼼꼼히 확인하자.

### DFS/BFS

DFS는 한 경로를 깊게 탐색하고, BFS는 가까운 노드부터 탐색한다. 방문 처리를 잊지 말자.

### 정렬

선택 정렬과 삽입 정렬은 기본 원리를 이해하기 좋다. 실전에서는 파이썬 기본 정렬을 우선 고려하자.

### 이진 탐색

정렬된 데이터나 단조로운 조건에서 탐색 범위를 절반씩 줄인다. 경계 인덱스를 주의하자.

### DP

큰 문제의 답을 작은 문제의 답으로 구성하고, 중복 계산을 저장하여 제거한다. `dp[i]`의 의미부터 정의하자.

### 최단 경로

다익스트라는 하나의 출발점에서 다른 노드까지, 플로이드 워셜은 모든 노드 쌍 사이의 최단 거리를 계산한다.

### 그래프 이론

Union-Find는 집합 관리, 크루스칼은 최소 신장 트리, 위상 정렬은 선후 관계 처리에 사용한다.

## 11. 마무리

### 11.1 첫 번째 복습 메모

알고리즘 공부에서 중요한 것은 단순히 정답 코드를 외우는 것이 아니라고 생각한다.

실제 코딩테스트에서는 이전에 봤던 문제와 완전히 똑같은 문제가 나오지 않을 수 있기 때문이다.

따라서 풀이를 외우는 것보다 문제를 읽었을 때 어떤 알고리즘을 사용할 수 있는지 판단하는 기준을 익히는 것이 중요하다.

그리디에서는 현재 선택이 왜 최적해로 이어지는지 설명할 수 있어야 한다.

이진 탐색에서는 어떤 근거로 탐색 범위를 절반씩 버릴 수 있는지 이해해야 한다.

앞으로 알고리즘 문제를 정리할 때도 정답 코드보다 **문제를 보고 풀이 방법을 떠올리는 과정**을 중심으로 기록하려고 한다.

### 11.2 전체 학습 메모

코딩테스트 알고리즘을 공부할 때는 단순히 정답 코드를 외우는 것보다, 문제의 특징을 보고 적절한 알고리즘을 떠올릴 수 있어야 한다.

특히 알고리즘의 이름을 아는 것과 실제로 구현할 수 있는 것은 다르다.

따라서 각 알고리즘을 복습할 때는 다음 세 가지를 확인하려고 한다.

1. 어떤 문제에서 사용하는가?
2. 왜 그 방식으로 정답을 구할 수 있는가?
3. Python으로 직접 구현할 수 있는가?

문제를 풀다가 막혔다면 단순히 정답을 확인하는 것에서 끝내지 않고, **어느 부분에서 알고리즘의 원리를 이해하지 못했는지** 기록하는 것이 다음 문제를 해결하는 데 더 도움이 될 것이다.
