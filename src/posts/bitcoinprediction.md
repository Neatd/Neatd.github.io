## 1. 프로젝트를 시작하며

비트코인 가격의 한 시간 뒤 움직임을 예측하는 문제에 도전했다. 가격 자체를 회귀하는 대신, 다음 시간의 가격 변화율을 네 구간으로 나누어 분류하는 프로젝트였다.

6명이 약 2주 동안 온체인 데이터와 거래소 시장 데이터를 분석하고, 전처리·피처 엔지니어링·모델 실험을 나누어 진행했다. 팀은 최종 보고한 정확도 **42.56%, 최종 리더보드 3위**로 프로젝트를 마쳤다. Wrap-up의 베이스라인 40.90%와 비교하면 **1.66%p 향상**한 결과다.

나는 도메인 리서치와 EDA를 바탕으로 **EMA·Wavelet 등 시계열 피처를 설계하고, Open Interest를 탐색하며, 여러 모델을 비교하는 작업**에 집중했다.

## 2. 문제를 정확히 정의하기

### 2.1 예측한 것은 가격이 아니라 변화 구간

변화율은 개념적으로 다음과 같이 표현할 수 있다.

```text
r(t+1) = [close(t+1) / close(t) - 1] × 100
```

| 클래스 | 다음 시간의 가격 변화율 |
| --- | --- |
| 0 | -0.5% 미만 |
| 1 | -0.5% 이상, 0% 미만 |
| 2 | 0% 이상, 0.5% 미만 |
| 3 | 0.5% 이상 |

예를 들어 다음 시간 변화율이 -0.7%라면 클래스 0, +0.2%라면 클래스 2다. 방향뿐 아니라 변동 폭도 구분해야 했다.

### 2.2 클래스가 네 개라고 기준 정확도가 25%는 아니다

데이터에서는 작은 변동인 클래스 1·2가 많고, 큰 변동인 0·3은 적었다. 균등하게 무작위 예측한다면 기대 정확도는 25%지만, 불균형 데이터에서는 다수 클래스만 예측하는 기준 모델도 그보다 높은 정확도를 얻을 수 있다.

따라서 결과를 해석할 때는 정확도뿐 아니라 **클래스별 Precision·Recall, 혼동행렬, AUROC**를 함께 봐야 했다. 급등·급락을 거의 놓치면서 다수 클래스만 맞히는 모델인지 구분하기 위해서다.

## 3. 데이터를 합치기 전에 데이터의 의미부터 보기

### 3.1 온체인 데이터와 시장 데이터

전체 제공 자료는 107개 CSV로 구성되어 있었다. 파일마다 지표, 거래소, 심볼 등이 달라, 같은 시각을 기준으로 여러 데이터를 결합해야 했다.

| 구분 | 지표 예시 | 살펴본 관점 |
| --- | --- | --- |
| 온체인·네트워크 | 해시레이트, 난이도, UTXO, 거래 수, 공급량, 활성 주소 | 블록체인 활동과 네트워크 상태 |
| 시장·파생상품 | Open Interest, 펀딩 비율, 청산, 매수·매도 거래량, 프리미엄 | 시장 참여와 포지션 관련 정보 |

피처 이름에는 단순한 지표명뿐 아니라 출처가 들어 있어야 했다. 예를 들어 서로 다른 거래소의 `open_interest`를 같은 이름으로 합치면 의미를 잃거나 충돌할 수 있다.

후기 베이스라인에서는 파일명과 원래 컬럼명을 조합해 출처를 보존했다.

```text
시간 ID
  ├─ 거래소 A의 Open Interest
  ├─ 거래소 B의 Open Interest
  ├─ 청산·거래량·펀딩 지표
  └─ 네트워크 지표
          ↓
    시간 기준으로 결합한 학습 표
```

### 3.2 결측치는 숫자 처리 이전에 원인을 확인해야 했다

EDA 과정에서 일부 데이터가 2022년까지만 수집되어 이후 구간을 합칠 때 결측이 생긴다는 점을 확인했다. 이런 경우는 중간에 몇 개 빠진 관측값과 다르다.

| 결측 유형 | 먼저 확인할 질문 |
| --- | --- |
| 일부 시점만 누락 | 수집 오류인가, 해당 시점의 관측이 없는가? |
| 특정 시점부터 전부 누락 | 제공 기간이 끝난 것인가? |
| 특정 거래소·심볼만 누락 | 해당 시장이나 지표가 실제 존재하는가? |
| 값이 0 | 정말 관측값 0인가, 누락을 대신한 표기인가? |

그래서 모든 열을 무조건 채우는 것보다, 학습과 추론 양쪽에서 사용할 수 있는 정보인지 먼저 살폈다. 보간 방법도 비교했고, 프로젝트에서는 선형 보간을 활용했다.

다만 나중에 돌아보면 보간은 **실제 예측 시점에 알 수 있는 값만 사용하는가**까지 확인해야 하는 작업이었다. 미래 관측값을 이용하는 보간과 실시간 전처리는 같은 조건이 아니다.

### 3.3 상관관계는 피처를 찾는 출발점

개인 EDA에서는 레이블 분포와 결측치를 확인하고, 변수 간 상관계수 히트맵을 그렸다. 가격과 UTXO·Open Interest의 시계열도 비교했다.

처음 눈에 들어온 것은 Open Interest와 가격의 움직임이었다. 반면 UTXO처럼 함께 증가하는 지표는, 서로 관련이 있다기보다 각자 장기 추세를 가진 결과일 수도 있다고 생각했다.

여기서 중요한 구분은 다음과 같다.

> 가격 수준과 비슷하게 움직이는 지표를 찾는 것과, 다음 시간의 가격 변화 구간을 예측하는 것은 다른 문제다.

시각적 유사성이나 상관관계는 가설의 근거가 될 수 있지만, 미래 예측력을 증명하지는 않는다. 이후 피처를 만들고 별도의 평가에서 확인하는 과정이 필요했다.

## 4. 내 중심 작업: 시계열을 모델이 읽을 수 있는 특징으로 바꾸기

초기에는 원래 지표와 과거 값을 붙이는 Shift 피처를 사용했다. 여기에 추세·변화·여러 시간 범위의 정보를 추가하는 방향으로 실험을 확장했다.

### 4.1 EMA: 최근 변화에 더 큰 비중 주기

지수 이동 평균은 최근 관측값에 더 큰 비중을 주어 추세를 요약한다.

```text
재귀형 EMA의 기본 형태
EMA(t) = α × x(t) + (1-α) × EMA(t-1)
α = 2 / (span + 1)
```

코드에서는 Pandas의 `ewm(span=...).mean()`으로 피처를 만들었다. 위 수식은 직관을 위한 재귀형 설명이고, Pandas 기본 설정의 초기 구간 가중 정규화까지 그대로 나타낸 식은 아니다.

개인 노트북에는 span 7을 적용한 실험이 남아 있다. 원래 값과 함께 사용해, 모델이 현재 수준과 최근의 평활화된 흐름을 모두 볼 수 있도록 했다.

단순한 변환이지만, ‘방금 지표가 얼마인가’에서 ‘최근 흐름 안에서 어떤 상태인가’로 표현을 확장하는 의미가 있었다.

### 4.2 Wavelet: 여러 시간 규모의 변동을 분해하고 재구성하기

Wavelet 변환은 신호를 여러 스케일의 근사·세부 성분으로 나누어 분석하는 방법이다. 시간 위치와 변동 규모를 함께 살펴볼 수 있어 비정상적인 시계열 표현을 탐색하는 데 사용했다. [PyWavelets 다단계 분해 문서](https://pywavelets.readthedocs.io/en/latest/ref/dwt-discrete-wavelet-transform.html)

개인 코드의 처리 순서는 다음과 같았다.

```text
지표 시계열
  → 이산 Wavelet 다단계 분해
  → 세부 계수에 soft threshold 적용
  → 역변환으로 시계열 재구성
  → 재구성된 값을 새 피처로 추가
```

| 구현 요소 | 개인 코드에서 사용한 설정 |
| --- | --- |
| 라이브러리 | PyWavelets |
| Wavelet | `db5` |
| 분해·재구성 | `wavedec`, `waverec` |
| 경계 처리 | `mode="per"` |
| 임계 처리 | 세부 계수에 soft threshold |
| 임계값 예시 | `0.6 × 입력 신호의 최댓값` |

핵심 목적은 작은 변동을 완화한 표현을 모델에 추가하는 것이었다. 다만 **고주파 성분이 모두 노이즈이고 제거한 성분이 모두 쓸모없다는 뜻은 아니다.** 급격한 변화 자체가 예측에 필요한 신호일 수도 있다.

또한 이 임계값은 실험에 사용한 휴리스틱이다. 지표 스케일이나 극단값에 민감할 수 있어 보편적인 최적 설정으로 보지는 않는다.

### 4.3 보고된 성능과 다음에 확인할 조건

Wrap-up 결과표에서 EMA+Wavelet을 사용한 LightGBM의 `Accuracy(final)`은 **0.4249**, 즉 42.49%다. 베이스라인의 40.90%와 비교하면 1.59%p 높다.

이 결과는 해당 대회에서 유용한 피처 후보를 찾았다는 기록이다. EMA와 Wavelet 각각의 효과를 완전히 분리한 인과적 결과나, 실제 실시간 예측 성능으로 확대하지는 않는다.

특히 전체 시계열을 한꺼번에 분해·재구성하면 과거 시점의 값에 이후 관측값이 영향을 줄 수 있다. 다음에 같은 실험을 한다면 **각 예측 시점까지의 데이터만 사용하는 과거 창 기반 변환**으로 다시 평가하고 싶다.

## 5. Open Interest: 수준·변화·맥락 나누기

Open Interest는 아직 청산되거나 반대 매매로 해소되지 않은 미결제 계약 규모를 나타내는 지표다. 거래량과 같은 뜻은 아니다.

나는 가격을 추론 입력에서 동일하게 사용할 수 없는 상황에서, Open Interest 등 다른 지표가 제공하는 정보를 탐색했다. ‘가격을 대체한다’고 확정하기보다는, 시각적으로 관찰한 움직임을 새로운 특징으로 표현해 보는 과정이었다.

### 5.1 차분과 변화율

```text
차분      = OI(t) - OI(t-1)
변화율    = OI(t) / OI(t-1) - 1
```

차분은 절대적인 변화량을, 변화율은 이전 수준에 대한 상대적 변화를 표현한다. 코드에서 `_pct_change`라고 이름 붙인 값은 그 자체로 통계적 변동성, 예를 들어 수익률 표준편차와 같은 것은 아니다.

또한 OI가 늘었다고 가격 상승이 결정되는 것은 아니다. 매수·매도 계약이 함께 존재하므로 가격·펀딩·청산 등 다른 정보와 함께 해석해야 했다.

### 5.2 Rolling: 여러 시간 범위의 맥락 붙이기

팀에서는 6·12·24·48개 시점의 이동 평균을 추가했다. 데이터가 한 시간 간격으로 정렬되고 누락 없이 이어졌을 때 각각 6·12·24·48시간의 창으로 해석할 수 있다.

| 표현 | 모델에 전달하려던 정보 |
| --- | --- |
| 현재 OI | 현재 수준 |
| 차분·변화율 | 직전 관측 대비 변화 |
| 6개 시점 평균 | 비교적 짧은 흐름 |
| 24·48개 시점 평균 | 더 긴 범위의 맥락 |

현재 값 하나에 모든 정보를 담으려 하지 않고, 같은 지표를 서로 다른 시간 범위로 표현한 것이다. 다만 48시간 이동 평균만으로 장기 상승장·하락장을 충분히 학습했다고 보기는 어렵다.

### 5.3 추가 도메인 피처

후기 코드에는 청산 관련 비율, 펀딩과 청산 차이의 조합, 프리미엄 차이, 해시레이트·난이도 비율, 공급 변화 비율 등도 정리되어 있다.

이런 특징은 도메인 가설을 식으로 표현한 후보들이다. 생성했다는 사실과 성능 개선에 기여했다는 사실은 구별해야 한다. Wrap-up에서도 여러 피처를 합친 설정이 모든 평가 열에서 좋아진 것은 아니었다.

## 6. 클래스 불균형: 무엇을 더 잘 맞힐 것인가?

불균형 대응은 표본 수를 같게 만드는 것만으로 끝나지 않았다. 팀은 오버샘플링, 샘플 가중치, 계층 분할, Focal Loss를 비교했다.

| 접근 | 의도 | Wrap-up에 기록된 관찰 |
| --- | --- | --- |
| SMOTE 계열·ADASYN | 소수 클래스 표본을 늘리기 | 방법별 차이, 전체 성능과 소수 클래스 성능 간 절충 |
| 시간창을 활용한 SMOTE 실험 | 시간 맥락을 고려한 증강 탐색 | Recall은 높지만 Precision·전체 지표가 낮아진 경우 |
| 샘플 가중치 | 소수 클래스 오류 비용 증가 | Recall 향상과 전체 Accuracy·AUROC 감소가 함께 나타남 |
| 계층 분할 | 학습·검증의 분포를 비슷하게 유지 | 분할 목적에 따라 유용하지만 추론 때의 분포를 보장하지는 않음 |
| Focal Loss | 쉽게 맞힌 표본의 기여를 줄이기 | Precision 향상, Recall 감소, 전반적 개선은 작음 |

이는 팀 차원의 실험 기록이다. 개인 기여의 중심은 피처 설계와 모델 비교였으며, 모든 불균형 실험을 단독 수행한 결과로 묶지는 않는다.

### 6.1 Focal Loss가 집중하는 것은 ‘어려운 표본’

일반적인 형태는 다음과 같다.

```text
FL = -α_t × (1 - p_t)^γ × log(p_t)

p_t: 정답 클래스에 부여한 확률
γ: 쉽게 맞힌 표본의 손실을 얼마나 줄일지 정하는 값
α_t: 클래스별 가중치에 사용할 수 있는 항
```

예를 들어 γ=2라면 정답 확률 0.9인 표본의 조절 계수는 0.01이고, 0.2인 표본은 0.64다. 쉽게 맞힌 표본의 손실을 더 크게 줄인다. 다만 어려운 표본과 소수 클래스가 항상 같은 것은 아니다. [Focal Loss 원논문](https://arxiv.org/abs/1708.02002)

### 6.2 성능이 좋아졌다는 기준도 나누어야 했다

소수 클래스 Recall이 올라도 경고를 과도하게 많이 내면 Precision은 낮아질 수 있다. 대회 전체 정확도를 목표로 할 때와 큰 변동 탐지를 목표로 할 때, 좋은 모델의 기준이 달라진다.

이번 실험에서는 많은 불균형 대응이 전체 지표 개선으로 이어지지 않았다. 효과가 작거나 목적에 맞지 않은 방법을 최종 조합에서 제외하는 것도 실험의 결과였다.

## 7. 모델을 바꾸며 확인한 것

### 7.1 트리 모델과 LSTM을 함께 탐색

개인 기록에는 Random Forest, LightGBM, XGBoost와 LSTM 비교가 남아 있다. Optuna를 사용해 하이퍼파라미터 탐색도 진행했다.

| 모델·도구 | 실험에서 살펴본 관점 |
| --- | --- |
| Random Forest | 기준 모델과 특징 중요도 탐색 |
| LightGBM | 피처 조합별 성능 비교의 중심 모델 |
| XGBoost | 다른 GBDT 구현과 비교 |
| LSTM | 순환 신경망 계열 모델 적용 가능성 탐색 |
| Optuna | 탐색 범위를 정한 하이퍼파라미터 실험 |

개인 회고에서는 LSTM에 Shift 피처를 추가한 경우와 제외한 경우도 비교했고, 제외한 설정이 더 좋아 보였다고 기록했다.

다만 저장된 초기 LSTM 코드는 입력의 시간 길이를 1로 구성한다. 따라서 그 노트북 하나만으로 ‘여러 시간의 순서를 LSTM이 충분히 학습했다’고 말하기는 어렵다. 모델 이름뿐 아니라 실제 입력 시퀀스의 구성도 함께 확인해야 한다는 교훈이 남았다.

### 7.2 앙상블은 팀 성과와 개인 시도를 구분하기

팀은 Bagging과 Soft Voting 등을 실험했다. Bagging은 표본을 달리 학습한 모델을 결합하고, Soft Voting은 모델들의 클래스 확률을 결합하는 방식으로 이해할 수 있다.

나는 개인 회고에 Voting 시도를 남겼다. 다만 시간 부족으로 LSTM까지 포함한 앙상블의 결과를 충분히 확인하지 못했다. 저장소의 일부 Bagging·Voting·Stacking 코드는 주석 처리된 실험안으로도 남아 있다.

최종 보고한 **42.56% Bagging은 팀 결과**다. 이 성과를 개인의 모든 앙상블 구현이 완료되어 검증된 결과와 동일하게 묶어 설명하지 않는다.

## 8. 결과를 숫자로 다시 읽기

Wrap-up 7쪽의 두 열 이름은 `Accuracy`와 `Accuracy(final)`이다. 아래는 그 표에서 주요 실험을 추린 것이다.

| 실험 | Accuracy | Accuracy(final) |
| --- | ---: | ---: |
| LightGBM, All Features | 0.3793 | 0.4090 |
| LightGBM, EMA 7 | 0.4020 | 0.4118 |
| LightGBM, EMA + Wavelet | 0.4070 | **0.4249** |
| LightGBM, SMOTE | 0.4041 | 0.4191 |
| LightGBM, ‘세연+유솔 피처’ | 0.4155 | 0.3988 |
| LightGBM, 해당 피처 + 결측치 앞뒤 보간 | 0.4148 | 0.4118 |
| LSTM + Bollinger Bands, 기록 중 한 설정 | 0.4027 | **0.4263** |
| Bagging, 최종 보고 설정 | 0.4162 | **0.4256** |
| Soft Voting | 0.3928 | 0.4068 |

이 표는 같은 모델의 변수를 한 번에 하나씩만 바꾼 완전한 통제 실험표는 아니다. 날짜별 모델·전처리·특징이 다른 탐색 기록이므로, 차이를 특정 기법 하나의 효과로 전부 돌리면 안 된다.

### 8.1 팀 최종 결과와 단일 실험 최댓값은 다르다

팀 Wrap-up은 최종 결과로 42.56%와 3위를 보고했다. 한편 실험표에는 LSTM+Bollinger Bands의 42.63%도 존재한다.

따라서 42.56%를 ‘실험 전체에서 나온 가장 높은 숫자’라고 부르기보다는 **팀이 최종 보고한 설정의 성능**이라고 정리한다. 최고 관측값과 최종 선택은 구분해야 한다.

### 8.2 1.66%p 향상의 의미

```text
베이스라인: 40.90%
최종 보고: 42.56%

정확도 차이 = 42.56 - 40.90 = 1.66%p
상대 정확도 증가율 = (42.56 - 40.90) / 40.90 ≈ 4.06%

오류율: 59.10% → 57.44%
상대 오류율 감소 = (59.10 - 57.44) / 59.10 ≈ 2.81%
```

작은 수치 차이도 정확도 차이, 상대 증가율, 오류 감소율 중 무엇인지 밝혀야 의미가 분명해진다.

또한 분류 정확도는 매매 수익률과 다른 지표다. 이 프로젝트는 거래 비용·슬리피지·포지션 관리까지 포함한 거래 전략의 수익성을 검증한 결과가 아니다.

## 9. 성과와 함께 남겨 둔 검증 과제

### 9.1 무작위 분할과 미래 예측 평가는 다르다

개인 노트북과 베이스라인에는 `train_test_split`을 이용한 무작위 분할이 사용된다. 이 조건은 과거만 학습하고 이후 시기를 맞히는 평가와 다르다.

시계열 데이터는 인접 표본이 유사하고 시장 상태도 바뀐다. 다음에는 다음과 같은 순서로 다시 검증하고 싶다.

```text
실험 1: 초기 기간 학습 → 그다음 기간 검증
실험 2: 학습 기간 확장 → 더 뒤 기간 검증
실험 3: 다시 확장    → 최종 미사용 기간 평가
```

시간 순서를 고려하는 분할은 이런 목적에 맞는다. 미래 라벨이 참조하는 구간과 예측 시점을 확인하고, 필요하면 학습과 검증 사이에 간격도 두어야 한다. [Scikit-learn TimeSeriesSplit 문서](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)

### 9.2 피처에도 예측 시점이라는 기준이 필요하다

| 처리 | 다음에 확인할 조건 |
| --- | --- |
| EMA·Rolling·Shift | 시간 정렬, 누락 시점, 현재 시간 집계값의 사용 가능 시점 |
| Wavelet | 해당 시점 이후 데이터를 보지 않는 변환인가? |
| 선형 보간·bfill | 미래 관측값을 사용하지 않는가? |
| 정규화·특징 선택 | 학습 데이터에서 기준을 정했는가? |
| 온체인 지표 | 관측 시각과 실제 공개·확정 시각이 같은가? |
| 오버샘플링 | 학습 구간 안에서만 수행했는가? |

대회 점수의 향상은 확인했지만, 현재 코드의 조건만으로 실시간 미래 예측에서 같은 성능을 보장하지는 않는다. 데이터가 흘러오는 순서대로 다시 계산하는 검증이 필요하다.

### 9.3 검증 지표와 최종 평가가 엇갈린 경험

‘세연+유솔 피처’ 실험은 `Accuracy` 열에서는 0.4155였지만 `Accuracy(final)`에서는 0.3988이었다. 특정 피처가 한 평가에서 좋아 보인다고 다른 구간에서도 좋아진다는 보장은 없었다.

이 경험은 다음의 필요성을 남겼다.

- 동일한 분할·전처리 조건으로 비교할 것
- 기간별 점수와 클래스별 오류를 함께 볼 것
- 피처를 하나씩 제거하는 실험으로 기여를 확인할 것
- 여러 번의 반복 결과와 변동 폭을 남길 것
- 최종 평가를 자주 보며 선택하는 과정의 편향을 관리할 것

## 12. 다시 설명할 때 기억할 질문

### 이 프로젝트에서 가장 중심적인 개인 기여는?

EDA를 바탕으로 EMA·Wavelet 같은 시계열 표현을 탐색하고, Open Interest 관련 가설을 세워 피처 설계와 모델 비교로 연결한 것이다.

### Wavelet을 왜 사용했나?

여러 규모의 변동을 분해하고 임계 처리한 재구성 신호를 추가해 다른 표현을 제공하려 했다. 실제 미래 예측에서는 과거 데이터만 사용하는 방식으로 다시 검증해야 한다.

### 불균형은 해결됐나?

여러 대응을 실험했지만 소수 클래스 지표와 전체 지표 사이의 절충이 있었다. 단순히 표본 수를 맞추는 것만으로 성능이 모두 개선되지는 않았다.

### 앙상블이 항상 좋았나?

아니다. 팀 표에서 Bagging은 최종 보고 설정에 포함되었지만 Soft Voting은 베이스라인보다 낮은 값도 기록했다. 결합 방식 자체보다 모델 조합과 평가 조건이 중요했다.

### 가장 확실하게 말할 수 있는 결과는?

팀 Wrap-up 기준으로 베이스라인 40.90%에서 최종 보고 42.56%로 1.66%p 향상했고, 팀은 최종 3위를 기록했다. 개인 피처 실험 중 EMA+Wavelet 조합은 42.49%가 보고되었다.

### 다시 한다면 무엇을 먼저 바꿀까?

공통 베이스라인과 실험 기록을 통일하고, 시간 순서 검증과 예측 시점 기준의 전처리부터 구축하겠다. 그 위에서 피처별 효과와 모델 결합을 다시 비교하고 싶다.
