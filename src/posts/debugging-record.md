## 관찰한 증상부터 적기

"안 된다"는 설명보다 어떤 입력에서 어떤 결과가 나왔는지를 적으면 다음 실험을 정하기 쉽습니다. 기대한 결과와 실제 결과를 나란히 놓습니다.

예를 들어 수량이 누락된 항목이 합계에 들어가는 상황을 생각해봅시다.

```javascript
const items = [{ count: 2 }, {}];
const total = items.reduce((sum, item) => sum + item.count, 0);

console.log(total); // NaN
```

## 가설을 하나씩 확인하기

두 번째 항목의 `count`는 `undefined`입니다. 여러 부분을 한꺼번에 바꾸기보다, 누락된 수량을 어떻게 처리할 것인지 먼저 정합니다.

이 예시에서는 누락된 수량을 0으로 취급합니다. 수량 누락 자체를 오류로 봐야 하는 서비스라면 다른 처리가 필요합니다.

```javascript
const total = items.reduce((sum, item) => sum + (item.count ?? 0), 0);

console.log(total); // 2
```

## 수정과 전제 조건을 함께 남기기

같은 코드도 데이터 규칙이 달라지면 적절하지 않을 수 있습니다. 수정 방법과 함께 선택의 이유를 남겨두면 다른 문제에 무작정 적용하는 일을 줄일 수 있습니다.

- 원인: 수량이 누락된 항목이 계산에 포함되었다.
- 처리: 이 예시의 규칙에 따라 누락된 수량을 0으로 계산했다.
- 확인: 빈 배열, 정상 배열, 누락된 항목이 있는 배열을 비교한다.

## 확인한 범위를 쓰기

문자열이나 음수 수량까지 다루었다고 말하려면 그 입력도 확인해야 합니다. **실제로 확인한 것과 아직 확인하지 않은 것을 구분하는 기록**이 다음 실험을 돕습니다.
