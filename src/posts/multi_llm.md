## 여러 LLM이 모이면 더 똑똑해질까?

LLM 여러 개가 서로 토론하고, 역할을 나누고, 함께 문제를 해결한다는 이야기를 보면 사람으로 구성된 팀이 떠오른다. 그런데 관련 논문을 읽다 보면 협력만큼이나 경쟁, 기만, 집단 편향도 자주 등장한다.

그래서 이번에는 멀티에이전트를 두 가지 질문으로 나눠서 보려 한다.

1. **여러 에이전트를 어떻게 연결해 작업을 수행할까?**
2. **서로 영향을 주고받는 에이전트 집단에서는 어떤 행동이 나타날까?**

이번에 읽은 자료들은 두 번째 질문에 가까운 연구가 많다. 코딩이나 검색을 분업시키는 시스템과, 가상의 사회에서 신뢰·전략·규칙을 관찰하는 실험을 같은 종류로 묶지 않는 것이 출발점이다.

## 1. 멀티에이전트가 곧 여러 종류의 모델이라는 뜻은 아니다

**모델은 판단에 사용하는 기반이고, 에이전트는 그 모델에 역할·기억·관측 범위·행동 방식을 결합한 실행 단위**로 생각하면 이해하기 쉽다.

```text
같은 LLM
├─ 에이전트 A: 기획자 역할 + A의 기억 + A가 볼 수 있는 정보
├─ 에이전트 B: 검토자 역할 + B의 기억 + B가 볼 수 있는 정보
└─ 에이전트 C: 실행자 역할 + C의 기억 + C의 도구 권한
```

같은 모델을 사용하더라도 에이전트별 상태가 분리되어 있고 상호작용한다면 멀티에이전트 시스템을 구성할 수 있다. 서로 다른 모델을 사용하는 구성도 가능하다.

| 구분 | 뜻 |
| --- | --- |
| 동일 모델 기반 집단 | 여러 에이전트가 같은 기반 모델을 사용 |
| 이종 모델 기반 집단 | 에이전트마다 서로 다른 기반 모델을 사용 |
| 역할 분리 | 기획·작성·검토 등으로 역할을 나눔 |
| 정보 분리 | 같은 사건에서도 서로 다른 사실을 관측 |

이 글에서는 LLM 기반 멀티에이전트를 **LLM-MAS**라고 부른다. 단순히 한 모델의 답변을 여러 번 뽑아 투표하는 ensemble과도 구분한다. 답을 독립적으로 모으는지, 다른 에이전트의 결과를 보고 다음 행동을 바꾸는지가 중요한 차이다.

또한 아래 실험에서 기억이 쌓여 행동이 달라졌다는 것을 모델 가중치가 매번 다시 학습되었다는 뜻으로 읽으면 안 된다. 대화와 행동 이력을 다음 입력에 넣는 방식으로도 변화가 생길 수 있다.

## 3. 출발점 ① Generative Agents — 기억하는 가상 마을

**질문:** 에이전트가 이전 경험을 기억하고 계획한다면, 더 일관된 행동과 상호작용이 나타날까?

Generative Agents는 Smallville이라는 환경에서 25개 에이전트의 생활과 상호작용을 다룬다. 중심 구조는 경험을 저장하는 **기억**, 경험을 더 높은 수준의 관찰로 종합하는 **reflection**, 이후 행동을 정하는 **계획**이다. 연구에서는 정보 확산과 관계 형성, 모임의 조율 등을 관찰했다. [논문 원문](https://arxiv.org/abs/2304.03442v2)

```text
주변 관찰 → 경험 저장 → 관련 기억 검색 → 계획과 행동
                    ↘ 경험을 종합한 reflection ↗
```

이 흐름을 보면 매번 독립적인 답변을 생성하는 것과, 과거 경험을 이어받는 에이전트의 차이를 이해하기 쉽다.

다만 평가에서 다룬 행동의 그럴듯함과, 실제 인간 사회에 대한 예측 정확도는 구분해야 한다. 가상 인물이 자연스럽게 대화한다는 사실만으로 실제 사람을 대신할 수 있다고 결론 내릴 수는 없다.

**기억할 문장:** 에이전트를 지속적인 존재처럼 보이게 만드는 데는 현재 프롬프트뿐 아니라 기억을 저장하고 다시 꺼내는 구조가 중요하다.

## 4. 출발점 ② AutoGen — 대화를 작업 흐름으로 만들기

**질문:** 서로 대화할 수 있는 에이전트들을 조합해 애플리케이션을 구성할 수 있을까?

AutoGen은 LLM, 사람, 도구 등의 능력을 결합한 에이전트 사이의 대화를 프로그래밍하는 프레임워크를 제안한다. 어떤 에이전트가 답하고, 실행 결과가 누구에게 전달되며, 사람은 어디에 참여하는지를 구성한다. [논문 원문](https://arxiv.org/abs/2308.08155v2)

예를 들어 다음은 이해를 위한 작업 분업 예시다. 논문의 특정 실험을 그대로 옮긴 것은 아니다.

```text
사용자 요청
   ↓
코드 작성 에이전트 → 실행 도구 → 실행 결과
          ↑                       ↓
          └──── 검토·수정 요청 ────┘
```

이 경우 소통은 목표를 완수하기 위한 수단이다. 반면 가상 사회나 게임 실험에서는 상호작용 자체가 관찰 대상이 된다.

여기서 읽은 내용은 2023년 논문의 설계다. 현재 라이브러리의 API나 설치 방법을 설명하는 글은 아니다.

**기억할 문장:** 작업을 분업하는 시스템과, 집단 행동을 관찰하는 시스템은 같은 기반 기술을 쓰더라도 평가 목적이 다르다.

## 5. Beyond Self-Talk — 몇 명인가보다 어떻게 소통하는가

**질문:** LLM-MAS를 소통 방식으로 분류하면 무엇이 보일까?

이 논문은 새로운 게임의 승률을 보고하는 실험 논문이 아니라 서베이다. 시스템 수준에서는 구조·목표·프로토콜을, 내부 소통에서는 전략·방식·대상·내용을 나눠 살펴본다. [읽은 버전: v3](https://arxiv.org/abs/2502.14321v3)

이 관점을 실제 설계 질문으로 바꿔보면 다음과 같다.

| 설계 질문 | 생각해볼 예시 |
| --- | --- |
| 누가 누구와 연결되는가? | 전원 대화, 관리자 중심, 역할별 팀 |
| 언제 발언하는가? | 차례대로, 동시에 작성한 뒤 취합 |
| 무엇을 전달하는가? | 자유로운 글, 코드, 구조화된 결과 |
| 목표는 같은가? | 협력, 경쟁, 둘이 섞인 상황 |

위 예시는 분류를 이해하기 위한 정리다. 특정 구조가 모든 작업에서 더 좋다는 결론은 아니다. 전원 대화는 정보 공유를 늘릴 수 있지만, 비용과 무관한 메시지도 늘릴 수 있다.

서베이가 지적하는 주요 과제에는 소통 효율, 확장성, 보안, 평가 체계가 있다. 에이전트를 추가할 때도 역할뿐 아니라 메시지 전달 경로와 종료 조건을 함께 설계해야 한다.

**기억할 문장:** 멀티에이전트의 설계 단위는 인원수만이 아니라 정보가 흐르는 방식이다.

## 6. Casevo — 사회적 관계망을 가진 에이전트 시뮬레이터

**질문:** 서로 다른 배경과 기억을 가진 에이전트가 관계망 안에서 상호작용하게 하려면 무엇이 필요할까?

Casevo는 Mesa 기반 사회 시뮬레이션 프레임워크다. 환경과 이벤트를 관리하는 모듈, 에이전트의 기억·판단 모듈, 병렬 요청 처리, 관계망 모듈을 나눈다. RAG와 단기·장기 기억 등을 활용해 다음 행동에 맥락을 반영한다. [논문 원문](https://arxiv.org/abs/2412.19498v1)

논문은 선거 토론 시나리오에서 에이전트가 내용을 보고 평가하고, 서로 논의하고, 성찰과 투표로 이어지는 사례를 제시한다.

```text
외부 사건 → 개인별 관측·기억 → 관계망을 통한 대화
                                     ↓
                             판단·행동·상태 갱신
```

여기서 흥미로운 점은 한 명의 답변뿐 아니라 연결 구조와 시간에 따른 상태 변화를 관찰할 수 있다는 것이다.

다만 시나리오 시연을 실제 선거 예측의 검증으로 해석하지는 않는다. 등장인물의 설정과 기반 LLM의 편향이 결과에 영향을 줄 수 있다. 이 연구에서는 구성 가능한 시뮬레이션 도구라는 기여를 중심으로 읽는 편이 적절하다.

**기억할 문장:** 사회 시뮬레이터의 표현력을 높이는 것과 현실 사회를 정확히 예측하는 것은 다른 검증이 필요하다.

## 7. 게임이론 연구 — 보상이 달라지면 협력도 달라질까?

**질문:** LLM의 전략적 행동은 보상 크기나 사용하는 언어에 민감할까?

FAIRGAME을 확장해 반복 죄수의 딜레마와 다자간 공공재 게임을 다룬다. 보상 크기를 조절하거나 집단 기여를 관찰하고, 행동 이력을 전략 유형으로 분류하는 지도학습 분석도 사용한다. [읽은 버전: v2](https://arxiv.org/abs/2512.07462v2)

보상·언어에 따른 행동 차이와 후반부 비협력 경향 등을 보고한다. 두 참가자의 실험은 별도 대화 없이 행동과 공개 이력으로 상호작용한다.

### 게임을 이해하기 위한 예시

공동 작업에서 모두 기여하면 팀 전체가 이득을 얻지만, 다른 사람이 기여할 때 자신은 비용을 내지 않고 혜택만 받고 싶을 수도 있다. 이런 개인 이익과 집단 이익의 긴장을 단순한 규칙으로 만드는 것이다. 이 예시는 이해용이며 논문의 보상표를 재현한 것은 아니다.

전략 분류를 실제 내면의 의도 측정으로 읽지는 않는다. 또한 4.3절은 여러 언어를 논의하지만 5절은 영어·베트남어로 범위를 제한했다고 적는다. 재현 시 조건 확인이 필요하다.

**기억할 문장:** 협력 성향은 모델 이름 하나에 고정된 속성으로 보기보다 규칙·보상·표현 조건과 함께 평가한다.

## 8. The Traitors — 잘 속이는 것과 잘 알아채는 것은 다르다

**질문:** 숨은 역할이 있는 게임에서 기만과 탐지는 같은 방향으로 좋아질까?

마피아 게임과 비슷한 환경이다. Traitor는 동료의 정체를 알고 탐지를 피하며, faithful은 대화와 투표로 정체를 추론한다. [읽은 버전: v2](https://arxiv.org/abs/2505.12923v2)

기본 실험은 traitor 3명, faithful 7명으로 모델별 10회다. 시행 안에서는 같은 기반 모델을 사용한다. 보고된 평균값은 다음과 같다.

| 평균 지표 | DeepSeek-V3 | GPT-4o-mini | GPT-4o |
| --- | --- | --- | --- |
| Traitor 생존율 | 0.33 | 0.33 | 0.93 |
| Faithful의 traitor 지목 투표 정확 비율 | 0.56 | 0.55 | 0.10 |

두 번째는 faithful의 지목 투표 중 traitor를 가리킨 비율이며 게임 승률과 다르다. 원문은 표준편차도 보고한다.

공격·방어에 같은 모델이 배치되고 시행도 적은 예비 결과다. 모델 크기에 관한 일반 법칙으로 해석하지 않는다.

**기억할 문장:** 설득력 있는 출력을 만드는 능력과, 타인의 잘못된 주장을 검증하는 능력은 별도로 평가해야 한다.

## 9. 기사 속 원 논문 — 같은 이름을 고르다 규칙이 생긴다

**질문:** 집단 전체를 지시하는 관리자가 없어도 공통 관습이 생길까?

무작위로 만난 두 에이전트가 유한한 후보에서 같은 이름을 고르면 점수를 얻고, 다르면 잃는다. 각자는 최근 상호작용만 기억하고 전체 상태는 보지 못한다. 기본 조건은 24명, 이름 후보 10개, 기억 길이 5회다. [Science Advances 원문](https://pmc.ncbi.nlm.nih.gov/articles/PMC12077490/)

```text
각자의 짧은 기억
      ↓
두 에이전트가 이름 선택 → 일치 여부 확인 → 각자 기억 갱신
      ↓ 반복
집단에서 공통 이름이 우세해지는 현상 관찰
```

저자들은 공통 관습의 출현, 특정 이름에 대한 집단 편향, 다른 규칙을 고집하는 소수 집단에 의한 관습 변화를 보고한다. 단독 검사에서 뚜렷한 편향이 검출되지 않은 조건에서도 집단 수준의 편향이 나타났다는 점이 중요하다.

주어진 후보의 조정이지 새 언어 전체의 발명이나 의식의 증거는 아니다. 관습을 바꾸는 소수 집단의 임계 비율도 보편 상수로 읽지 않는다.

여기서 배우는 것은 합의가 어떻게 생기는가다. 합의된 이름이 있다는 사실은 외부 사실에 관한 정답을 찾았다는 증거가 아니다.

**기억할 문장:** 개인 수준의 검사만으로 집단 상호작용에서 생기는 편향을 전부 예상하기는 어렵다.

## 10. 다 같이 같은 말을 하면 맞는 말일까?

이 부분은 개별 논문의 새로운 실험 결과가 아니라, 연구들을 읽으며 정리한 설계상의 질문이다.

예를 들어 세 에이전트가 같은 문서를 읽고 같은 결론을 냈다고 하자.

```text
잘못된 원문 하나
├─ A가 인용
├─ B가 A의 말을 신뢰
└─ C가 A와 B의 일치를 근거로 확신
```

화면에는 세 개의 동의가 있지만 독립적인 근거는 하나일 수 있다. 같은 모델을 서로 다른 역할로 호출해도 오류의 원인이 같다면 다수결의 이점은 제한될 수 있다.

그래서 다음을 분리해서 보려 한다.

| 관찰한 것 | 그것만으로 알 수 없는 것 |
| --- | --- |
| 에이전트끼리 합의함 | 외부 사실과 일치하는가? |
| 말이 설득력 있음 | 주장의 근거가 유효한가? |
| 협력적으로 행동함 | 목표가 올바르고 안전한가? |
| 사람처럼 대화함 | 실제 사람의 행동을 예측하는가? |
| 역할을 여러 개로 나눔 | 독립적인 검증이 추가되었는가? |

검토 역할을 붙였다는 사실보다, 그 역할이 원문·테스트·실제 실행 결과처럼 다른 근거에 접근할 수 있는지가 중요하다.

## 11. 직접 비교 실험을 한다면

다음은 앞으로 해볼 실험 설계다. 이 글에서 직접 실행한 결과는 아니다.

### 먼저 기준 시스템부터

1. 한 에이전트가 혼자 처리하는 구성.
2. 같은 예산으로 독립적인 답을 여러 번 만든 뒤 취합하는 구성.
3. 서로의 답을 보고 수정할 수 있는 멀티에이전트 구성.

세 번째가 더 잘하더라도 호출량과 토큰을 훨씬 더 썼다면, 역할 분리의 효과와 추가 연산의 효과가 섞인다. 비용이나 시간 예산을 맞춘 비교도 필요하다.

### 한 번에 하나씩 바꿀 조건

- 역할을 나누는가?
- 초안을 공유하기 전에 독립적으로 판단하는가?
- 모든 대화를 공유하는가, 필요한 근거만 전달하는가?
- 동일 모델 집단인가, 이종 모델 집단인가?
- 기억을 제거하거나 길이를 바꾸면 무엇이 달라지는가?

### 기록할 것

| 항목 | 기록 내용 |
| --- | --- |
| 품질 | 사전에 정한 정답·작업 성공 기준 |
| 신뢰 | 검증되지 않은 주장 수용, 근거 추적 가능성 |
| 비용 | 호출 수, 입력·출력 토큰, 실행 시간 |
| 안정성 | 반복 실행의 성공률과 변동 |
| 실패 | 무한 대화, 근거 없는 합의, 잘못된 도구 실행 |

단일 성공 사례만 보고 결론 내리지 않고, 실패 사례까지 남기는 것이 목표다.

## 12. 이번에 정리한 핵심

멀티 LLM 에이전트 연구는 하나의 방향이 아니다. 작업을 잘 나누는 설계, 상호작용을 구현하는 시뮬레이터, 게임을 이용한 행동 평가, 집단 규칙을 관찰하는 실험이 함께 존재한다.

내가 더 공부하고 싶은 것은 에이전트 수를 늘리는 방법보다 **무엇을 따로 관측하고, 어떤 근거를 공유하고, 어디서 검증할 것인가**다. 대화가 많아졌다는 사실과 검증이 좋아졌다는 사실을 구분해서 보고 싶다.

## 추가로 공부하기

- [ ] 동일 모델 집단과 이종 모델 집단을 같은 작업·예산으로 비교하기
- [ ] 모델의 자기 설명과 실제 행동 기록이 일치하는지 살펴보기
- [ ] 상대를 속이는 능력과 거짓 주장을 탐지하는 능력을 별도 실험으로 분리하기
- [ ] 게임의 보상·발언 순서·역할 분포를 바꾸어 결론이 유지되는지 보기
- [ ] 기억 제거, 대화 차단, 중앙 조정 제거의 ablation 설계하기
- [ ] 인간을 흉내 내는 시뮬레이션과 인간 데이터를 이용한 타당성 검증 구분하기
- [ ] 여러 에이전트가 같은 잘못된 근거를 재인용하는 현상을 추적하기
